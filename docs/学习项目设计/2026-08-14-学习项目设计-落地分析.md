# 学习项目设计 · 落地分析

> 源文档：`docs/学习项目设计/DS--调研分析--学习项目设计.md`  
> 核验日期：2026-08-14  
> 范围：对照现有幼儿工作台、核验开源引用、按课标与许可裁剪，给出可执行切片。  
> 本文是分析结论，不是“已实现”。

---

## 0. 结论先说

DS 文档的方向是对的：**不要做成闪卡工具，做成认 → 练 → 测 → 用 → 复的短时关卡。** 交互原则（大按钮、即时反馈、无惩罚、进度可见）也成立。

它现在还不能当实施说明书，原因有四条：

1. **和现有工作台脱节。** 识字专区、30 字种子库、60 日课程、1/3/7/14 复习规则、统一阳光账本都已经在仓库里；DS 文档当成从零开始，还要新建 `doudou_*` localStorage。
2. **引用有硬错误。** `cnchar.getWords` 不存在；官方库是 `theajack/cnchar`，组词 API 是 `cnchar.words()`。TSOFA 仓库路径写错。H5 组词来自 CSDN 文库，许可不明。
3. **许可会卡住复制。** `sdkks/flashcards_game` 是 CC BY-NC-ND 4.0（禁止修改再分发）。`go7th/kids-learning-cards` 是 PolyForm Noncommercial（个人/教育可用，不可商用、不宜整仓搬进运行时）。
4. **四周计划过载。** 五种卡片 + 1000 张 AI 图 + SM-2 + 四种游戏 + 新存储，第一件孩子看得见的东西会被拖死。

**最小可交付：先把已有 30 个生活字接到识字专区的认练测关卡，走现有阳光账本。** 组词、笔顺、扩库都排在这件之后。

## 3. 教学目标：按课标校准，不按 1000 字起跳

人教社文章转述《义务教育语文课程标准（2022 年版）》第一学段（1–2 年级）：**认识常用汉字约 1600，其中约 800 会写**。统编教材安排大致为一年级认 690、二年级认 910。课标还附《识字写字教学基本字表》**300 字**，建议先认先写。义务教育累计认识约 3500 字。  
一手文件应以教育部发布的课标文本为准；上文数量来自人教社《低年级识字教学的几点建议》（pep.com.cn，2025-12 PDF）。

幼小衔接工作台已有更贴身的目标（`docs/优化方案2/.../02-识字.md`）：

| 层 | 量 | 孩子当天看到什么 |
| --- | --- | --- |
| 现在就能玩 | 30 个生活字 | 今日 4–8 字，认练测各一轮 |
| 稳妥第一学期 | 60–80 字 | 按主题解锁，不出现年级标签 |
| 资料库上限 | 1000–1500 | 库要厚，每日要薄；不是一次压给孩子 |

DS 文档「第 1 批 300 字 AI 配图」跳过了 30 字已能玩的事实。人教社同时强调：**在语境中识字、适度字理、复现巩固、避免孤立识记、避免拔高。** 这比 SM-2 更接近幼儿产品。

SM-2（Wozniak，1987，SuperMemo 2）按易记因子算间隔，第一间隔 1 天、第二间隔 6 天，之后 `I(n)=I(n-1)×EF`，还要 0–5 质量评分。幼儿无法做这种自评。本仓库已经有 1/3/7/14 + 掌握态，**P0/P1 不要换算法。**

## 4. 数据层：三层保留，来源改真实

DS 的三层（核心数据 / 生成内容 / 用户数据）结构可用，但来源和存储必须改。

### Layer 1 核心数据（内置，人工审定）

不要运行时直接 `cnchar.words()` 出题。通用词典会给出「山寨、山洪、山魈」这类幼儿不该先学的词。

推荐主库字段（在现有 `[char, pinyin, theme, words[]]` 上扩展，而不是另写一套 YAML 运行时）：

```json
{
  "char": "山",
  "pinyin": "shān",
  "theme": "nature",
  "level": 1,
  "words": ["大山", "上山"],
  "example": "我们去看大山。",
  "image": "assets/generated/preschool/识字/shan.png",
  "audio": "assets/audio/hanzi/shan.mp3",
  "etymology": "像三座山峰。",
  "strokes": 3
}
```

扩库顺序：

1. 现有 30 字补全配图、例句、2 个儿童词。  
2. 按主题扩到 80（家人、身体、自然、动物、食物、颜色、数字、动作、学校）。  
3. 再从《通用规范汉字表》一级 ∩ 课标 300 基本字 ∩ 生活高频里人工抽到 300。  
4. 1000+ 只作为资料上限，不作为本季度玩法目标。

拼音表（23 声母 / 韵母 / 整体认读）和英语词继续走已有 `data/preschool/拼音`、`英语`、`english/phonics`，不要用「第五种数字卡」挤进识字关卡。数字已有数学专区。

### Layer 2 生成内容（可批量再生）

| 资产 | 推荐 | 不推荐 |
| --- | --- | --- |
| 读音 | 预生成 mp3（Edge TTS `zh-CN-XiaoxiaoNeural`），缺则 Web Speech 回退 | 运行时每次调云 TTS |
| 配图 | 本仓库已有 Imagine / 素材工厂路径；缺图时**纯大字也可玩** | 把 pollinations 当运行时依赖；风格无法保证 |
| 笔顺 | Hanzi Writer + 本地 `hanzi-writer-data` 子集 | 声称已有 165 字却无文件 |
| 字源/演变 | 人工短句；字形演变可链到汉字叔叔，不自造古文字图 | 批量 AI 编字源（易错） |

`kids-learning-cards` 的 YAML 批量生成适合**离线内容工厂**，产物是 HTML 卡 / 图 / mp3，再拷进 `prj/assets`。工作台运行时只读 JSON + 静态资源。

### Layer 3 用户数据

继续写 `storage.js` 现有结构：

- 课程完成：`completedLessonIds`（已有）  
- 掌握：按字记录 `introduced | practicing | ready | maintenance` + 最近正确率 + 下次复习日  
- 错题：已有错题本，`review-rules.json` 已规定 `storeIn: mistakes`、`sunlightDeduction: 0`  
- 阳光：现有 `growth.sunlight`，完成关卡走 canonical 奖励事件，禁止重复刷

## 5. 玩法裁剪（YAGNI）

### P0 必须有（识字专区，30 字）

闭环缩短为三步，单次 3–6 分钟：

| 步 | 孩子做什么 | 实现要点 |
| --- | --- | --- |
| 认 | 大字 + 拼音 + 可选图，点按发音 | 按钮 ≥ 52px；自动或点按读音 |
| 练 | 字↔图 或 字↔词，2–4 对 | 对对碰；错了回正，不扣阳光 |
| 测 | 听音点字，2–4 选 1 | Web Speech / 本地 mp3；对了短反馈并自动下一题 |

顶条只显示「认 / 练 / 测」，当前高亮。完成写入掌握态并发一次阳光（若该课尚未领过）。

### P1 值得做（同一字库）

- **组词开花**：核心字 + 6 个选项里选出 2–3 个正确儿童词。干扰词必须也是儿童词，不能用词典垃圾词。  
- **找字**：目标字混在 6–8 个形近/同主题干扰项中。  
- **组词配对（4×4）**：只在该字已有 ≥8 个审定双字词时开启。先不要 6×6。

### P2 以后再说

- Flip 3D 翻转动画（认步的大卡已经够）  
- 计时 60 秒组词挑战（幼儿容易变成刷分）  
- 五种卡片统一渲染引擎  
- SM-2 / FSRS  
- 跟读评分（Web Speech Recognition 在 iOS 不稳定，规则里已写 `speechRecognitionRequired: false`）  
- 数字卡并入识字（与数学专区重复）

洪恩「玩认练写说」里，**写**用 Hanzi Writer 描红即可，**说**用点读 + 家长确认，不要做 AI 学伴。

## 6. 技术约束（对着现栈）

工作台是静态前端：`preschool-workbench/index.html` + `app.js` + 数据 JSON。不要为了字卡引入 Preact/Python 运行时。

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 运行时框架 | 继续现有原生 JS | 与课程弹窗、阳光、导航同一路径 |
| 卡片生成 | 离线脚本，不进浏览器 | Python 生成器与幼儿点击路径无关 |
| 汉字工具 | 需要时 CDN/`vendor` 引入 `cnchar` + `pinyin-pro` | 官方地址，不用错误 fork |
| 笔顺 | 可选加载 Hanzi Writer | 无数据不阻塞认练测 |
| 存储 | 现有 snapshot | 导入导出、家长备份已经通 |
| 许可 | 自研轻量实现 | ND 协议代码不能改；NC 生成器不进商用包 |

`GameEngine` 统一四模式是过早抽象。P0 三个函数即可：`renderRecognize`、`renderPractice`、`renderQuiz`，数据都来自当前字的 bank 记录。

## 7. 修订后的实施切片

原「第 1 周数据层 / 第 2 周五种卡 / 第 3 周三种游戏 / 第 4 周打磨」改为四条可独立验收的切片。每条都有入口、首件、停止点。

### 切片 A — 字库真正出题（首件，1–2 天）

**输入：** `prj/data/preschool/识字/character-bank.json` 全部 30 字  
**入口：** 识字专区 → 今日练习弹窗  
**首件：** 孩子能对「山」走完认→练→测；界面不再出现「坡 / 始 / 游」作为今日主字  
**写入：** 只改识字练习渲染与 `config.js` 样例，进度走现有 `completeLesson`  
**停止点：** 若练习仍用手写 options 而不是读 bank，本切片未完成

验收：

- 抽 3 个字（我、山、猫），每字 认有读音、练能配对、测能听选。  
- 完成一次只加一次阳光。  
- 刷新后进度还在。

### 切片 B — 复习队列接上现规则（1 天）

**输入：** `review-rules.json`  
**首件：** 昨天练过、正确率 ≥ 0.8 的字，今天出现在「再认一次」而不是当新字  
**停止点：** 不要为此实现 SM-2 或 FSRS

### 切片 C — 组词开花（1–2 天）

**输入：** bank 里每字已有的 `words[]`，人工补到每字 2 个儿童词 + 3 个干扰词  
**首件：** 「山」能选出「大山 / 上山」，选「火山」也可（若收入），选「山寨」则不应出现在选项里  
**停止点：** 禁止运行时调用 `cnchar.words()` 直接出题

### 切片 D — 扩库到 80 字 + 配图/音频覆盖（内容工厂，按天追加）

**输入：** 主题表（家人、身体、自然、动物、食物、颜色、动作、学校）  
**首件：** bank 从 30 → 80；缺图仍可玩；音频优先预生成 mp3  
**参考字表：** 课标 300 基本字 ∩ 生活主题，而不是一级表 3500 全灌  
**停止点：** 未人工审词之前，不开放 300 字关卡

笔顺、拼音专区复用引擎、英语卡，全部排在 D 之后。

## 8. 风险与明确不做

| 风险 | 处理 |
| --- | --- |
| AI 字源事实错误 | 字源只保留一句已审短句；无则隐藏模块 |

## 9. 家长向验收句

- 孩子能不能在识字专区、不读长说明的情况下，用手指完成今天几个字的认练测？  
- 这几个字是不是生活里用得到的（我/你/山/水/猫），而不是「坡/始」？  
- 做完有没有留下阳光和学习证据，并且刷新后还在？  
- 错了会不会被扣分或听到刺耳惩罚音？

做不到这四句，就还在方案层，不进入五种卡片和 SM-2。

> 日期：2026-08-06

> 正式文档位置：`G:\StudyCode\个人工作台\docs\优化\`
> 结论先行：60 日课程资料继续保留，但不把它们全量塞进工作台首页；工作台只负责今天的行动、简单测试、完成记录、阳光/成长反馈和出口，完整趣味互动集中在独立的“花园保卫战”。

## 1. 本轮要解决的问题

当前工作台不能只是一张“有任务的草坪图”。参考案例真正有效的地方，是孩子能在一个很短的路径里看懂四件事：

1. 我是谁，正在和谁一起成长。
2. 今天先做哪一小步。
3. 做完以后留下了什么证据，得到了什么即时反馈。
4. 还想继续时，可以去哪里玩、兑换或查看成长。

因此本轮优化不以“增加更多课程卡片”为目标，而是把首页收敛为一条可重复的游戏化学习闭环：

```text
今日行动 → 完成证据 → 阳光/成长/连续行动 → 伙伴与花园变化 → 下一步或独立游戏
```

这条链路必须与课程资料解耦。资料库可以很丰富，首页不应该因此变成课程目录、题库和战斗棋盘的混合页面。

### 2.2 参考资料共同验证的设计原则

- **任务要小而明确**：孩子应能从卡片直接完成或进入下一步，不需要先理解一套管理术语。
- **奖励要即时但不替代证据**：阳光是即时反馈；完成状态、轻量测试结果、阅读记录才是可回看的证据。
- **成长要可见**：伙伴、等级、连续行动、植物解锁、成就墙比单纯的积分数字更容易让孩子理解“我变好了”。
- **游戏要承接学习，不要反过来支配学习**：游戏只读取已完成的行动和资源，不负责判定课程是否学会。
- **家长配置要有边界**：任务可改名、增删和导入导出；课程资料和奖励规则不是首页临时生成的内容。
- **持续迭代优于一次性堆功能**：案例中的 2.0 重点是反馈节奏，不是功能数量竞赛。

### 2.3 参考资料的限制

这些笔记主要保存了公开文章的文字摘要、OCR 和截图，没有给出可验证的原始代码、数据模型或完整教学效果实验。因此本项目只迁移交互模式和信息架构，不把“案例中出现过”写成“本项目已实现”，也不复制案例的角色、截图、音效或文案。

## 3. 当前产品边界

### 3.1 工作台负责什么

幼儿版首页和今日页只承担以下五件事：

1. 显示今天的任务与完成状态。
2. 允许孩子完成/取消一项可编辑的今日计划。
3. 进入一个简单练习或测试，并显示完成后的结果入口。
4. 展示阳光、连续行动、伙伴等级和学习证据摘要。
5. 提供“去花园游戏”“去领奖励”等明确出口。

### 3.2 资料库保留什么

60 日自然拼读、暑假学习单、识字、古诗、数学、英语、运动与专注等内容继续保存在 `data/` 和对应 `docs/` 资料包中，作为后续活动和打印材料来源。资料完整不等于网页课程引擎完成。

本轮明确不做：

- 首页全量读取 60 日课程 JSON。
- 把所有学科改成完整课程平台。
- 在首页嵌入整套题库、逐题教学或长流程课程引擎。
- 用复杂战斗逻辑参与学习判定或奖励结算。

### 3.3 独立游戏负责什么

“花园保卫战”承载植物选择、放置、角色技能、僵尸波次、动画和战场操作。它可以读取工作台产生的阳光与豌豆能量，但不能直接修改学习完成状态，也不能因失败扣除已获得的学习资源。

## 4. 本轮落地结构

### 4.1 首页四层结构

| 层 | 页面内容 | 真实入口/代码 | 用户看到的结果 |
| --- | --- | --- | --- |
| 身份层 | 专属伙伴、等级、阳光、连续行动、豌豆能量、下一步 | `renderPreschoolHomeIdentity()` | 先知道“我是谁”和“现在该做什么” |

### 4.2 统一事件顺序

一次学习行动必须遵循：

```text
用户动作
  ↓
稳定 activity/event id
  ↓
保存完成状态或测试结果
  ↓
recordAction / 既有奖励服务校验幂等
  ↓
增加阳光、成长或豌豆能量
  ↓
重新渲染首页、成长和游戏可读状态
```

重复点击、刷新、返回页面不能重复发放阳光。游戏中的豌豆命中、僵尸倒下等表现只属于游戏状态，不得另造一套学习积分账本。

### 4.3 首页视觉方向

参考案例的“冒险基地/花园”气质可以保留，但需要为幼儿阅读和触控做减法：

- 主色：草地绿、阳光黄、天空蓝、土壤棕；警报色只用于入侵状态。
- 结构：一个伙伴身份卡 + 一个今日战场 + 一个证据区；不再叠放两套导航或两套任务面板。
- 卡片：圆角、厚边框、轻微内阴影，按钮尺寸优先于装饰细节。
- 文字：中文由 HTML/CSS 渲染，生图只提供透明角色和装饰，不把文字烘焙进图片。
- 动效：每屏最多突出 1–2 个关键反馈；尊重 `prefers-reduced-motion: reduce`。
- 响应式：横屏保留侧栏，竖屏允许手动收起；移动端任务战线纵向排列，不出现横向滚动。

UI 检索得到的辅助建议也与此一致：儿童学习界面适合圆润、块状、明快的视觉语言；进度必须显式显示；不要让多个角色同时无限抖动；动效需提供减少动效降级。项目仍保持本地优先，不为字体或装饰引入运行时网络依赖。

## 5. 当前实现状态与真实缺口

### 已落地

- 首页有伙伴/等级/阳光/连续行动/豌豆能量身份区。
- 今日任务可在草坪战线直接完成，任务仍沿用现有可编辑计划和奖励幂等链路。
- 首页有“今天留下了什么”证据区，至少显示今日完成数、最近阅读记录和下一张学习路线入口。
- 首页不嵌入完整课程活动，不渲染独立战斗棋盘。
- 花园游戏、奖励中心、成长页和学习专区都有明确出口。
- 新样式单独放在 `css/preschool/24-game-study-loop.css`，没有把全部幼儿样式继续塞进一个更大的文件。
- 三个入口页脚版本统一到 `v0.4.4`；观察到浏览器仍命中旧资源后，幼儿入口 CSS、配置和主脚本缓存参数提升到 `20260806-game-study-loop-v3`。

### 仍未完成或刻意冻结

- 首页的“学习证据”目前是摘要层，不是每个任务都强制上传照片、语音或作业文件；这符合轻量工作台边界，但不能表述为完整学习档案。
- 60 日课程仍是资料库，不是首页已接入的 60 日课程引擎。
- 花园保卫战是独立 MVP，不是完整原版植物大战僵尸复刻；复杂关卡、多人、联网排行榜和复杂 AI 仍冻结。
- APK 自动编译、MuMu 安装验收、GitHub Pages/仓库发布需要独立发布任务，不能从本轮页面测试推导为已完成。
- Supabase 不属于当前线上后端；项目使用现有本地优先和自托管 API 边界。

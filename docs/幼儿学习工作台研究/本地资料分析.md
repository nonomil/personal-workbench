## 3. 当前缺口

### 3.1 文档缺口

- 现有 `docs/plans/` 是按日期堆叠的设计记录，缺少一个按“总方案/分方案/总计划/分计划”维护的稳定目录。
- 自然拼读的研究已经有较完整专项补充，但外部来源、许可证和内容 QA 没有进入主项目 canonical docs。
- “六学科四段式”只描述理念，尚未写出每一科的每日时长、活动类型、成功证据、复习间隔和失败降级。
- 奖励方案描述了阳光和花园，却没有把每日事件、课程完成、复习、家长确认和防重复写成数据合同。

### 3.2 内容缺口

- 现有幼儿学习素材可以开箱即用，但还不是一个有阶段门槛、复习队列和家长观察记录的内容库。
- 自然拼读 60 日数据、词库、短句库和复习规则已经生成并通过专项 QA；网页运行时目前不读取这套 JSON。
- 工作台最小闭环只要求三项核心打卡、可折叠可选项、一个简单测试入口、奖励记录、本地持久化和独立游戏出口；完整课程浏览与沉浸式游戏不属于本轮运行目标。
- 语数英之外的识字、古诗、运动与专注仍缺少统一的可观察产出字段。

### 3.3 工程缺口

- 方案需要对应到实际入口：`overview`、`garden`、`checkin`、`courses`、`mistakes`、`rewards`、`parent`、`settings`。
- 课程页、今日页和首页推荐必须使用同一个活动实例 ID，否则会重复发阳光。
- 现有大文件仍需模块化，但本次先冻结数据和验收边界，不在研究整理时进行全量重构。

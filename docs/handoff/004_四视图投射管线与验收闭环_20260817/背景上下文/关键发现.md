# 关键发现

> 一句话结论：模型难看的根因不是生图质量，而是"图 → 模型"之间靠人眼转录、
> 没有机械化像素通道；补上投射编译器 + 四向对比验收门后，模型与参考图逐格对齐。

## 断层诊断（已验证）

原流程：GPT 生四视图（好看）→ AI 看图**手写** three.js 盒子坐标和程序贴图
（`hideMat`/`faceOf` 噪点填充）→ 模型和图对不上（动物黑头、村民无脸、
铁傀儡纯灰）。

问题拆解：

1. **几何转录有损**：人眼估比例，盒子尺寸/位置和图不一致。
   → 修法：cuboid 规格改用公开 ModelRenderer 尺寸（specs.json），不再估。
2. **贴图完全断开**：参考图的像素根本没进模型，贴图是代码里编的噪点。
   → 修法：`fourview-to-atlas.py` 把每个盒每个面从对应视图机械裁切。
3. **无验收回路**：模型只在透视相机下瞄一眼，问题被角度掩盖。
   → 修法：`compare-four-view.html` 正交四向渲染 vs 参考图并排，逐格对比。

## 社区调研结论（2026-08，详见工具包调研文档）

| 路线 | 适用 | 本项目采用 |
| --- | --- | --- |
| A. 皮肤优先：固定盒骨架 + 64×64 UV 皮肤（skinview3d 式） | 标准人形 | 未用（村民帽袍非标准皮肤布局） |
| B. cuboid spec 编译：图 → 规格 + 像素图集 → 模型（img2blockbench 式） | 任意盒模型 | **本地简化版已落地** |
| C. Blockbench MCP agent 精修 | 高保真单体 | 备选，未接 |
| 通用 image-to-3D（TRELLIS 等） | 平滑网格 | **禁用于运行时资产** |

## 验收方法发现（用户提出，已验证有效）

"模型四向截图 vs 生图对比"这一验收门在本轮连续抓出 6 个真实缺陷
（背景漏色、侧脸全灰、五官错位、手臂灰斑、鼻子双重渲染、bbox 被分隔线撑爆），
每一个在单角度浏览下都不可见。已作为硬性门写入
`gpt-game-asset-pipeline/SKILL.md` 的 Non-negotiable gates。

# 根因分析

## 根因结论

本轮 APK 安装失败的直接根因是 MuMu 已安装同包名但不同签名的旧包；下载超时是网络传输路径问题。两者分别通过卸载旧包和 10808 代理解决，不能混为一个 APK 构建故障。

## 原理链

1. 输入：GitHub Release `v0.5.2` APK。
2. 传输：`curl.exe --proxy http://127.0.0.1:10808 --location --fail`。
3. 校验：文件大小与 SHA-256 对照发布记录。
4. 安装：ADB 检查旧包签名；发现 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。
5. 处理：用户确认后卸载 `com.nonomil.personalworkbench`，再执行 `adb install -r`。
6. 校验：安装返回 `Success`，`MainActivity` 前台，截图和日志确认启动。

## 证据等级

- **已验证部分**：下载、哈希、安装、启动和首个花园跳转均有本轮命令输出或截图。
- **推测部分**：完整三主题/练习/持久化路线可能正常，但尚未有设备级证据，必须标为待验证。
- **反证/冲突**：旧总控文档仍写 APK 未安装，这是文档滞后，不是对本轮设备证据的反证。

## 最小反证实验

- **实验名**：在同一已安装 APK 上执行根入口三主题点击与重启状态检查。
- **若失败意味着**：不要继续改发布文档为完成；定位具体主题路由、WebView 资源或 localStorage 持久化故障，再做最小修复。

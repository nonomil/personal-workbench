# 决策记录

## 决策 1：根入口采用两层五入口

- **选择**：三个幼儿游戏世界在上，成人和儿童通用工作台在下。
- **原因**：幼儿游戏入口是当前吸引孩子的主入口，成人/少儿工作台仍保留；五个入口不复制业务内核。
- **证据**：`index.html`、`tests/release-contract.test.mjs`、`docs/plans/2026-08-06-workbench-launcher-home-ux.md`。

## 决策 2：三种幼儿主题共用一个工作台合同

- **选择**：植物大战僵尸式花园、我的世界式方块探险、马里奥式闯关只改变视觉主题和入口参数。
- **原因**：避免三套任务、积分和 localStorage 分叉。
- **禁用替代**：不要把三个主题做成三个独立长期项目。

## 决策 3：资料库和工作台运行时解耦

- **选择**：60 日课程和各学科资料包继续保留，但首页只展示轻量任务和简单测试入口。
- **原因**：主控已明确工作台不承担完整课程平台；复杂游戏集中到独立游戏环节。
- **禁用替代**：不把 60 日 JSON 全量读取进首页或新增复杂课程引擎。

## 决策 4：APK 设备验收使用有效 Release 文件

- **选择**：用 10808 代理下载完整 Release APK，校验后在 MuMu 中卸载签名冲突旧包并重装。
- **原因**：直接 CDN 传输曾超时，旧包签名不一致会阻止更新安装。
- **限制**：卸载已清除 MuMu 内旧测试数据；这不代表真实用户数据被清除。

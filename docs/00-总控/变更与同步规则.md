# 变更与同步规则

## 1. 文档层级

```text
项目总控
  ├─ 当前状态 / 总路线图 / 进度看板 / 决策记录
  ├─ 幼儿课程总控
  │    ├─ 学科分方案与分计划
  │    └─ 资料、授权、实施验收
  ├─ 研究证据
  └─ 日期型设计与实施记录
```

优先级从上到下：项目总控约束范围，课程总控约束幼儿学习闭环，学科文档约束内容，研究资料只提供证据，日期计划记录历史过程。

## 2. 什么时候必须更新总控

- 增加或删除入口、页面、课程、奖励、存储 key、路由或发布渠道。
- 改变主目标、阶段顺序、技术边界或版权策略。
- 测试基线发生变化，尤其是失败、恢复或新增门禁。
- 从 worktree 合并一项会影响主项目的功能。

## 3. 代码改动同步清单

| 改动类型 | 必须同步 |
| --- | --- |
| localStorage/schema | `docs/data-model.md`、当前状态、对应测试 |
| 奖励/阳光/豌豆 | 幼儿课程数据与奖励合同、重复结算测试 |
| 课程数据 | 对应学科方案、资料计划、schema/QA 测试 |
| 路由/入口 | README、部署说明、静态入口测试 |
| APK/Pages | 发布计划、版本说明、构建证据 |
| 外部资料/图片 | 研究来源、许可证清单、发布白名单 |

## 4. Worktree 规则

- worktree 可以写实现计划，不能建立第二个长期总控。
- worktree 的文件完成后，先核对主项目当前状态，再以小批量提交合并。
- 不复制 `raw/`、下载缓存、截图和临时生成物到正式发布目录。
- 不因为目录重复而直接删除文件；先登记来源、引用关系和可恢复方案。

## 5. 任务关闭规则

任务必须同时具备：实现文件、验证命令或手工步骤、失败路径说明、下一阶段影响判断。缺任一项，状态保持“待验收”。

# 决策记录

## D-001：正式文档放主项目 docs

- 日期：2026-08-02
- 决定：`G:\StudyCode\个人工作台\docs` 是正式方案、调研、资料和进度的唯一来源。
- 原因：worktree 会随分支变化，不能承担长期知识库职责。
- 影响：worktree 里的计划只能作为实施草稿，完成后回写主项目 docs。

## D-002：设置两级总控

- 日期：2026-08-02
- 决定：项目级总控放 `docs/00-总控/`，幼儿课程总控保留在 `docs/幼儿课程方案/00-总控/`。
- 原因：三个入口需要共享发布、测试和状态规则，但幼儿课程又需要独立的学科合同。
- 影响：两级总控不能互相复制全文，子总控只引用项目总控的边界。

## D-003：先做 14 天 MVP

- 日期：2026-08-02
- 决定：先验证短活动和奖励闭环，再扩展 60 日全量内容。
- 原因：当前代码和资料已经较重，但内容库和测试尚未达到完整课程的质量门槛。
- 影响：60 日课程、复杂战斗、同步和 APK 暂列冻结项。

## D-004：植物大战僵尸作为反馈机制

- 日期：2026-08-02
- 决定：幼儿版保留植物、阳光、豌豆和入侵者，但不复制原版角色和完整塔防规则。
- 原因：学习价值来自活动闭环，复杂战斗会扩大开发和素材版权风险。
- 影响：动画和战斗只订阅学习状态，不能参与学习判定或奖励结算。

## D-005：资料先分析，缺口再联网搜索

- 日期：2026-08-02
- 决定：先分析项目现有资料和代码，再用 Tavily/Firecrawl 补具体缺口。
- 原因：当前已经有外部证据存档，重复搜索不会自动提高方案质量。
- 影响：每次新增外部资料必须说明它解决了哪个具体决策问题，并登记来源和授权。

## D-006：工作台轻量化，趣味集中到游戏

- 日期：2026-08-03
- 决定：工作台负责今日打卡、简单测试、进度、阳光、奖励和备份；游戏负责动画、角色、战场和趣味互动。
- 原因：这个产品的主要价值是帮助孩子完成和记录行动，不是替代教材或承担完整学习平台；把课程、战斗和动画全部塞进工作台会增加复杂度并降低可用性。
- 影响：60 日课程资料保留为资料库，按需逐科接入；首页不显示完整课程引擎；植物大战小游戏保持独立入口；游戏失败不扣打卡结果和已有资源。

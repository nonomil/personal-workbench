# WorkBuddy 结构调研

## 已核实事实

### 1. 页面骨架

参考页面使用 `#app` 作为全屏容器，页面由固定宽度的 `#sidebar` 和可滚动的 `#main` 组成。主区包含固定高度的 `#topbar`，下方是 `#content` 内容容器。

### 2. 导航与状态

左侧导航把功能拆成多个独立入口，每个入口同时提供图像、短文字和激活态。顶部状态条集中显示当前模块、阳光数量和孩子身份，孩子不需要在每张卡片里重新寻找关键状态。

### 3. 首页信息层级

花园基地首页先显示阳光、植物数量和僵尸状态，再显示花园棋盘和今日任务。任务清单以“一项任务一行”的方式呈现，完成状态、任务名称、简短说明和奖励并列，点击区域明显。

### 4. 视觉系统

参考 CSS 使用奶油色/浅蓝背景、白色卡片、黄色阳光状态、绿色完成状态和橙色主色。卡片使用较大的圆角和较弱的投影；主要层级由留白、颜色和字号完成，而不是密集的边框和深色游戏 HUD。

### 5. 反馈节奏

任务完成后通过阳光数量、任务完成态和短时庆祝反馈形成即时闭环；植物、花园、奖励商城和日历是连续使用的长期反馈入口。

## 设计推断

- 幼儿版首页应该是一张“今天的行动板”，而不是一张完整的战斗场景总览。
- 植物大战适合单独入口；首页只保留花园安全状态和一小块植物伙伴预览。
- 入口图标应比说明文字更突出，但任务卡仍需要短标题，避免只有图形无法确认动作。
- 现有 PVZ 素材可以成为内容主体，背景和容器应该退到低对比度，避免素材与面板互相竞争。

## 本项目采用

1. 幼儿版外壳继续使用 `preschool-workbench/index.html` 与现有路由，不创建第二个应用。
2. `app.js` 的幼儿概览渲染改为 WorkBuddy 式的三段首屏：今日任务、花园预览、奖励/连续打卡。
3. 新增最后加载的幼儿视觉层 `css/preschool/15-workbuddy-overview.css`，将新样式与历史像素级联隔离。
4. 现有 `PersonalWorkbenchStorage`、`PersonalWorkbenchPreschoolGarden`、奖励事件和 `petbank_huchuliang_preschool_workbench_state_v1` 保持不变。
5. 植物摆动、僵尸扭动、阳光脉冲继续保留，并在 `prefers-reduced-motion` 下关闭位移动画。

# 03 范围边界与决策门

## GATE-0：迁移基线

进入任何写任务前必须确认：

- `prj/` 含完整运行源。
- 旧根目录删除均有 `prj/` 对应项或明确废弃证据。
- 当前用户改动有可恢复提交、补丁或外部备份。
- `npm test`、`release:verify` 和语法检查的真实结果已记录。

未通过时只允许调查，不允许清理和重构。

## GATE-1：产品减法确认

用户确认：

- 根入口三卡，而不是幼儿三主题占三卡。
- 幼儿五导航的名称和归并关系。
- 首页只保留状态、任务、反馈、出口。

未确认时可做测试草案和静态原型，不替换正式入口。

## GATE-2：幼儿真实使用

五导航和首页完成后，在浏览器或设备完成一次：任务 → 练习 → 阳光 → 游戏 → 返回 → 冷启动。只有没有 P0/P1 阻塞，才拆 `app.js`。

## GATE-3：删除旧 CSS

每个旧 CSS 文件删除前必须有：

- 选择器引用/覆盖审计。
- 目标页面已迁移到新层。
- 多尺寸截图或 computed-style 证据。
- 定向与全量测试通过。
- 独立可回滚提交。

## GATE-4：素材清理

raw/reference/split 等只能在 runtime manifest、artifact 测试和备份来源都确认后移出发布目录。删除原始研究资料还需用户单独授权；本专项默认只做“不发布”，不做物理删除。

## GATE-5：远端发布

commit、push、tag、Release、Pages 和 APK 是独立授权。源码测试通过不自动授权发布。

## 必须写决策记录的变更

- 重新变成五个或更多根入口。
- 修改现有 localStorage key/schema。
- 引入框架、构建器、后端或 Supabase。
- 删除原始素材、历史 worktree 或旧根源码。
- 改变任务奖励、游戏奖励上限或家长确认规则。

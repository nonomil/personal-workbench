# 00 测试、验收与发布门禁总则

## 1. 基础命令

```powershell
npm test
npm run release:verify
node --check prj/app.js
node --check prj/storage.js
node --check prj/config.js
npm run android:prepare
```

重构后新增入口脚本也必须逐一 `node --check`。

## 2. 产品验收矩阵

| 场景 | 预期 |
| --- | --- |
| 首次打开根入口 | 只显示成人、少儿、幼儿三张主卡 |
| 首次进入幼儿 | 无主题记忆时选择主题；选择后记住 |
| 再次进入幼儿 | 自动使用已记住主题；设置可切换 |
| 幼儿主导航 | 只有今天、学习、游戏、奖励、我的 |
| 今天 | 3 核心任务；选做默认折叠；游戏和奖励出口可用 |
| 学习 | 学科二级展示；练习完成只发一次奖励 |
| 游戏 | 三世界可进入、返回；工作台首页没有棋盘/Canvas |
| 奖励 | 消费阳光；家长确认状态正确 |
| 我的 | 日历、成长、错题、家长、设置和备份可达 |

## 3. 数据验收

- 使用拆分前快照启动拆分后代码。
- 任务、阳光、能量、成长、奖励、三游戏进度一致。
- 三主题互切后读取同一幼儿快照。
- 刷新和冷启动后状态保持。
- JSON 导出、清空测试环境、导入后状态一致。
- 同一 eventId 重放不重复奖励。
- 无效导入不覆盖有效数据。

## 4. 浏览器尺寸

至少验证：

- 320×568
- 375×812
- 390×844
- 844×390
- 1024×768
- 1280×720
- 1440×900

每个尺寸检查：无横向滚动、固定导航不遮挡、dialog 可关闭、44px 触控、焦点可见、减少动效生效。

## 5. 性能与制品

- 首页 Network 不加载暑假完整数据和三个游戏全部资源。
- 首页 JS/CSS 数量和体积有拆分前后对比。
- `dist/` 不包含 raw/reference/split/失败响应。
- 运行时所有图片路径 HTTP 200。
- 大图没有用 2000px 原图显示在小卡片中。
- APK 记录最终大小及 Web assets 分项大小。

## 6. APK 与 MuMu

只有以下步骤全通过才能写“APK 验收完成”：

1. GitHub Actions 构建成功。
2. 下载完整 APK，记录文件大小和 SHA-256。
3. MuMu `adb install -r` 成功。
4. 根三入口可见。
5. 幼儿主题选择和五导航可用。
6. 完成一个任务，获得奖励，进入游戏，再冷启动。
7. 冷启动后状态保持。
8. logcat 无业务 FATAL。

Debug 包、正式签名包和商店发布必须分别描述。

## 7. Pages

- 根入口、三个工作台、三个游戏深层路径均 HTTP 200。
- 所有运行素材来自白名单制品。
- 旧幼儿主题 URL 至少一个发布周期可重定向/兼容。
- 不能用本地成功代替远端证据。

## 8. 阶段退出门禁

| 阶段 | 必须满足 |
| --- | --- |
| Phase 0 | 当前测试基线明确，迁移有恢复点 |
| Phase 1 | 三卡入口和主题记忆浏览器通过 |
| Phase 2 | 幼儿五导航、首页、奖励幂等通过 |
| Phase 3 | 三模式按需加载，存储兼容通过 |
| Phase 4 | CSS 旧层减少，视觉和可访问性通过 |
| Phase 5 | artifact 白名单和体积门禁通过 |
| 发布 | Actions、Pages、APK、MuMu 形成独立证据 |

任何阶段发现数据丢失、重复奖励或路由不可达，应立即停止后续阶段。

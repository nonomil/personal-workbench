# 00 总实施计划

> **给 Grok Build/Codex：** 按任务顺序执行；每个任务先补失败测试，再做最小修改，再运行定向和全量测试。不要在一个提交中同时改产品结构、存储 schema、CSS 和发布脚本。

**目标：** 在保持三套工作台数据兼容和三款小游戏可用的前提下，完成入口减法、幼儿五导航、渐进模块化和发布素材白名单。

**技术栈：** Vanilla JS、HTML、CSS、localStorage、Node `--test`、Capacitor 8、GitHub Actions。

---

## Phase 0：建立可恢复基线

### 任务 0.1：核验迁移状态

**只读文件：** 根目录、`prj/`、`scripts/`、`tests/`、`.github/`。

步骤：

1. 运行 `git status --short`，保存摘要，不修改现有 700 项变化。
2. 运行 `npm test` 和 `npm run release:verify`。
3. 运行 `node --check prj/app.js`、`prj/storage.js`、`prj/config.js`。
4. 对照 `scripts/prepare-mobile.mjs` 组装一次临时 `dist/`，记录文件数和体积。
5. 确认 `prj/` 是当前唯一运行源，旧根删除不是唯一副本。

**停止条件：** 测试失败、`prj/` 缺失关键文件、用户迁移尚无可恢复提交时，不进入 Phase 1。

### 任务 0.2：建立优化测试清单

**修改：** `tests/release-contract.test.mjs`、`tests/launcher.test.mjs`，必要时新增 `tests/preschool-navigation.test.mjs`。

先写当前目标的失败断言：三主卡、幼儿五导航、旧路由兼容、存储 key 不变。此时测试应因当前五卡/17 导航而失败。

## Phase 3：JavaScript 渐进模块化

### 任务 3.1：建立 runtime/adapter 接口

**创建：** `prj/js/core/` 和 `prj/js/preschool/` 最小文件。

**修改：** `prj/app.js`、三个入口 HTML、相关合同测试。

旧 `app.js` 暂时保留兼容代理。新模块缺失必须显示错误，不静默空白。

### 任务 3.2：抽取幼儿纯函数和素材解析

先迁移主题 playbook、素材 resolver、路由 helper；测试输入输出，不依赖 DOM。

### 任务 3.3：逐页抽取

顺序：today → learning → games → rewards → profile。每页单独提交；每次确认：

- HTML 语义未回退。
- action 仍只有一个 owner。
- 页面离开清理完成。
- 奖励没有重复。

### 任务 3.4：按需课程数据

幼儿首页不再加载 `preschool-summer-learning-data.js`。仅进入对应资料页时加载，失败有提示。相关请求在 Pages、APK WebView 和本地 HTTP 下验证。

### 任务 3.5：成人与少儿 adapter

幼儿稳定后分别抽取成人、少儿。三个入口只加载共享 core + 当前 adapter。

## 每阶段提交规范

- 一次提交只解决一个边界。
- 提交前运行定向测试和 `npm test`。
- 发布相关阶段额外运行 `npm run release:verify`。
- 不自动提交用户无关的脏工作树。
- 不自动推送、打 tag、替换 Release 资产，除非用户另行明确授权。

# 01 数据兼容与迁移方案

## 1. 受保护存储

优化不得修改或清空以下事实来源：

| 模式 | localStorage key |
| --- | --- |
| 成人 | `petbank_huchuliang_adult_workbench_state_v1` |
| 少儿 | `petbank_huchuliang_child_workbench_state_v1` |
| 幼儿 | `petbank_huchuliang_preschool_workbench_state_v1` |
| 最近模式 | `personal_workbench_selected_variant_v1` |
| 幼儿主题 | `personal_workbench_selected_preschool_theme_v1` |

三幼儿主题必须继续读取同一个幼儿 key。

## 2. 本轮数据原则

产品减法和代码拆分原则上不需要修改幼儿 schema。导航分组、首页区块和按需加载属于表现层变化，不得借机升级数据结构。

如果必须新增字段：

1. 在 `storage.js` 的规范化函数中提供默认值。
2. 保留未知字段，避免导入导出丢失未来数据。
3. 旧快照首次读取时只补缺失，不覆盖用户改名、完成状态、自定义任务和奖励记录。
4. 写入失败必须返回可观察失败，不能继续显示完成或发奖。
5. 增加旧快照夹具和迁移测试。

## 3. 奖励链路

任务、课程和游戏继续使用稳定事件 ID：

```text
用户动作
→ 保存完成事实
→ 校验 eventId/receipt
→ 发放阳光、能量或成长
→ 保存奖励记录
→ 重新渲染
```

禁止：

- 页面渲染函数直接改阳光。
- 同一任务因“打卡”和“轻量练习”各发一次奖励。
- 游戏失败扣除学习所得。
- 重构期间建立临时第二账本。

## 4. JSON 导入导出

重构前后必须验证：

- 成人导出后可恢复成人数据。
- 少儿导出后可恢复少儿数据。
- 幼儿任一主题导出，在另一个主题导入后保持任务、阳光、成长和游戏进度。
- 凭证和 API token 不进入业务快照。
- 无效 JSON、错误模式和损坏 schema 给出明确提示，不覆盖当前有效数据。

## 5. 路由兼容

保留现有外部可访问路径：

- `/prj/成人成长工作台/`
- `/prj/儿童学习工作台/`
- `/prj/preschool-workbench/`
- `/prj/games/garden-defense/`
- `/prj/games/voxel-adventure/`
- `/prj/games/platform-quest/`

幼儿旧 hash 如 `#overview`、`#courses?course=...` 可在路由层映射到新五导航，不要求旧收藏链接立即失效。映射至少保留一个发布周期。

## 6. 回滚

- 每个阶段开始前保存测试通过的 Git 提交。
- 不通过删除用户 localStorage 来解决迁移问题。
- 新模块加载失败时可以临时回退旧 adapter，但不得让新旧两套同时结算奖励。
- 任何数据不一致都优先停止发布，保留现场并导出快照。

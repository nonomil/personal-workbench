# 01 · Echo Loop 分析与许可边界

分析对象：`prj/games/Echo-Loop-main`（Flutter 英语听说训练 App，AGPL-3.0）。
本文提炼「思路和方法」，供方块传奇与工作台清房重写（clean-room）使用。

## 1. 它解决什么问题（产品叙事）

Echo Loop 的痛点定位不是「缺学习材料」，而是两件事：

1. 换新材料成瘾，一段材料从来没练透；
2. 用户知道「盲听→精听→跟读→复述→复习」的方法，但每一步都要自己决策，意志力被决策消耗殆尽。

它的解法是**把「下一步做什么」产品化**：App 用状态机自动推进学习阶段，用户打开 App 只看到「今日任务」，照做即可。这是全项目最值得借鉴的一条。

## 2. 核心机制提炼（按可借鉴度排序）

### 2.1 阶段机 + 今日任务队列（P0）

- 每段材料一条进度记录，大阶段线性推进：`首学 → 复习0/1/2/4/7/14/28 → 通关`；
- 首学内部再拆子步骤：精听 → 跟读 → 盲听（可跳过）→ 复述；
- 今日任务排序固定：**到期复习 > 未到期复习 > 首学**；
- 复习间隔是**固定课表**（相对上一轮完成时间）：6h → 1d → 2d → 4d → 7d → 14d → 28d，不是逐词 SRS。对「整段材料/整个关卡」这种粗粒度对象，固定课表比 FSRS 更可控、叙事更清晰；
- 到期后有宽限窗口（6h~24h），超时标 overdue 但任务仍可做；支持手动提前解锁、暂停后原地恢复；
- 学习计划带**版本快照**：流程升级时存量进度用旧计划、新内容用新计划，产品可迭代而不炸老用户。

### 2.2 跟读评测：ASR + 宽松词对齐（P0）

评测不做发音声学打分，流水线是：

1. ASR（平台语音识别 / 离线模型 / 纯录音降级三档）；
2. 文本匹配：只取英文词 → 小写 → **词形还原（lemmatize）** → token 级 **LCS** 对齐；
3. 覆盖率 = 命中词 / 目标词，≥0.5 算通过；输出两侧高亮片段；
4. 分级阈值按场景区分：跟读严（Perfect≈0.95）、复述宽（Perfect≈0.90、Fair≈0.20）。

结论：**「ASR + 覆盖率 + 分场景阈值」就足以支撑跟读闭环**，不需要云端发音打分。

### 2.3 难句自动归档 → 专项补练（P1）

精听时点「听不懂」→ 自动收藏难句（带上下文、AI 解析）→ 复习轮的主任务就是只练这些难句。避免「标了就忘」。

### 2.4 语境闪卡（P1）

收藏的词/意群做成闪卡，但翻面时**播放它所在的原句音频**——词永远绑语境，不是孤立卡片。排序用简化超期比例（期望间隔 ≈ 60min × 2^练习次数），没有 Again/Hard/Good/Easy 四键。

### 2.5 素材三件套（P1）

每条材料 = 音频 + 句级时间轴（SRT）+ 词级时间轴（words.json：`word/start/end/confidence`）。词级时间戳支撑意群播放、逐词高亮；没有词级数据时用「按字符比例合成」的近似兜底。内容按 CEFR A1–C2 分级。

### 2.6 学习统计抓「输入/输出」（P2）

统计维度：streak、**输入词数 vs 输出词数**（听 vs 说）、输入/输出时长、**唯一词形量**（lemmatize 后去重）。比「答题数/金币数」更贴听说目标，适合做家长报告。

### 2.7 FSRS 基础设施的架构方法（P2，只抄架构不抄实现）

Echo Loop 建了 FSRS 基建但**尚未接入业务**，其架构设计值得记下：

- 应用自有 `MemoryScheduler` 接口，FSRS 库只出现在 adapter 层；
- 调度数据独立成表，不往词/句/材料实体上塞算法字段；
- **当前快照 + 只追加的 review 事件流**：可审计、可重放迁移；
- 每项固定算法 Profile 版本，升级不重排存量。

对我们的启示：工作台 mastery 升级时，先加「复习事件追加日志」，把接口和数据分开，未来想换算法（含 FSRS）不用迁移地狱。

### 2.8 工程方法（P2）

- 复杂流程提取为**可单测的纯逻辑引擎**（播放循环、跟读流程、闪卡流程），UI 只组装——blocklegend 已有纯函数 + `node --test` 的传统，方向一致；
- 异步用 session/generation 守护防旧回调污染；
- 音频文件按 SHA256 去重落盘。

## 3. 刻意不借鉴的清单

| 不抄什么 | 原因 |
| --- | --- |
| AGPL 代码本体（Dart/Kotlin/资源） | 许可红线，见 §4 |
| 完整 FSRS 接入 | Echo Loop 自己都没接；固定课表 + 简化超期排序够用 |
| 波形 auto-align、词级时间戳全链路 | 我们的素材是单词+短句，不是长音频，暂无场景 |
| 云端发音声学打分 | 覆盖率评测已够；国内网络环境不可靠 |
| Riverpod/Drift 架构、订阅体系 | 技术栈不同（我们是原生 JS + localStorage） |

## 4. AGPL-3.0 合规边界（2026-08-19 用户确认后的口径）

1. **版权保护"表达"，不保护"思想"**：阅读源码、学习算法设计、提取阈值参数、对照理解后自己重写——全部合法，任何情况下都安全。**允许在实施时直接参考源码**，不要求 clean-room 净室流程（那是商业诉讼场景的过度防御）；
2. **AGPL 义务只在两种情况触发**：对外分发（发 APK 给他人、上商店、公开仓库）或提供网络服务。纯私人使用即使复制代码也不违反协议；
3. **唯一纪律：不复制粘贴它的代码和资源文件**。原因不是当下违法，而是保留将来发布 APK / 公开仓库 / 自选协议开源的自由——抄过的行会成为无法剥离的地雷；
4. 仓库卫生（已落实）：`prj/games/Echo-Loop-main/` 已加入 `.gitignore`；`Echo-Loop-main.zip` 被既有规则 `prj/games/*.zip` 覆盖。目录保留在本地作参考，永不入库（入了 git 历史再公开仓库即构成"分发"其副本）；
5. 为减少实施会话翻源码的需要，关键算法与参数已提炼至 [`04-机制参数速查.md`](./04-机制参数速查.md)。

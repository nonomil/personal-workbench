来源：2026-08-19 对 Echo-Loop-main 源码的逐文件提炼。本文是**算法与数值层**的速查，实施 E1–E4 / 工作台升级时优先看这份，减少翻原仓源码。

## 1. 跟读评测流水线（E1 `speech-match.js` 的蓝本）

### 1.1 Tokenize

- 正则只抽英文词：`[A-Za-z]+(?:'[A-Za-z]+)?`（支持 `don't`），丢数字/中文/标点；
- 全部小写 → 逐 token 词形还原（§1.4）→ 还原为空则丢弃；
- 保留每个 token 在原文的 `[start, end)` 字符区间，供高亮用。

### 1.2 LCS 对齐（token 级，保序）

标准 DP + 回溯：

```text
dp[i][j] = ref[i-1]==hyp[j-1] ? dp[i-1][j-1]+1 : max(dp[i-1][j], dp[i][j-1])
回溯：相等时双退并记录两侧下标；否则 dp[i-1][j] >= dp[i][j-1] 优先上移
```

保序意味着乱序说不能全中（`the cat sat on the mat` vs `mat the cat sat` → 3/6）。输出两侧命中下标集合。

### 1.3 覆盖率与判定

- `score = 命中 token 数 / 目标 token 数`；
- 识别文本无英文词 → `noEnglishDetected`，score=0；
- **流程通过阈值 `score >= 0.5`**（这是"能不能推进"，与 UI 评级分离）。

高亮片段：按原文扫描，词间非匹配字符与每个英文词切成 `Segment(text, isMatched)`，目标句与识别文本各生成一份。

### 1.4 词形还原

Echo Loop 用第三方 `lemmatizerx`（MIT，仿 NLTK WordNet morphy：不规则表 + 词性后缀剥离，词典约 2.3MB）。取第一个非空 lemma，找不到返回原词。

**我们的裁剪**：597 词幼儿词表不需要 2.3MB 词典。自建即可——不规则表（词表内实际出现的 ~50–100 条：`went→go`、`children→child`…）+ 规则后缀剥离（`-ies→y / -es / -s / -ed / -ing`，注意辅音双写如 `running→run`）。接口只需 `lemma(form) → baseForm`。

## 2. 评级阈值（注意档名是 Excellent，不是 Great）

| 档位 | 跟读 | 复述 |
| --- | --- | --- |
| Perfect | ≥ 0.95 | ≥ 0.90 |
| Excellent | ≥ 0.80 | ≥ 0.75 |
| Good | ≥ 0.60 | ≥ 0.50 |
| Fair | ≥ 0.40 | ≥ 0.20 |
| KeepGoing | 其余 | 其余 |

从上到下取第一个满足档。**评分低不阻断推进**（有录音就往下走）——这条产品原则务必保留。

## 3. 复习课表与窗口（E2 复习之门的蓝本）

### 3.1 间隔（距上一轮完成时间，链式，非累计里程碑）

| 轮次 | 等待 | 轮次 | 等待 |
| --- | --- | --- | --- |
| review0 | 6h | review4 | 48h |
| review1 | 18h | review7 | 72h |
| review2 | 24h | review14 | 168h |
| | | review28 | 336h |

链式累计 ≈ 28 天走完 7 轮。产品文案可以说"6小时/1天/2天/4天/7天/14天/28天"，实现按上表。

### 3.2 可学窗口 / 逾期

```text
nextReviewAt = lastStageCompletedAt + intervalHours
宽限窗：review0 → 6h；review1..review28 → 24h
isReady   = now >= nextReviewAt
isOverdue = now > nextReviewAt + 宽限窗
```

逾期只标记、不惩罚、任务仍可做（排序最优先）。

### 3.3 手动提前解锁（不篡改后续间隔）

- 解锁只写 `manualUnlockAt = now`，**不改** `lastStageCompletedAt`；
- 本轮完成推进时：`lastStageCompletedAt = 实际完成时刻`，清掉 `manualUnlockAt`；
- 下一轮 `nextReviewAt` 用真实完成时刻 + 下一档间隔 → 提前解锁只松当前锁。

## 4. 闪卡排序与倒计时（E3 图鉴/工作台今日词可用）

### 4.1 智能排序分（越大越靠前）

```text
从未练过 → 固定 2.0
否则：期望间隔 = 60min × 2^clamp(练习次数, 0, 30)
     超期比例 = 距上次练习分钟数 / 期望间隔
     得分 = clamp(超期比例, 0, 10)
```

### 4.2 智能倒计时（按词长与练习次数）

```text
ratio   = clamp((词长 - 4) / 8, 0, 1)
maxTime = 3 + ratio × 3   # 3s → 6s
minTime = 2 + ratio × 2   # 2s → 4s
decay   = clamp(练习次数 / 5, 0, 1)
秒数    = round(maxTime - decay × (maxTime - minTime))
```

（原仓注释写 4→8/2→5，代码实际 3→6/2→4，以代码为准。）

## 5. Plan 版本快照（E2 §2.4 / 工作台 mastery 方案 A 的蓝本）

- 每条进度持久化 `planVersionsByStage: {阶段: 版本号}`，新建时盖当前最新版本戳；
- 日常操作不改快照；代码升级后**存量走旧版、新建走新版**，无自动迁移；
- 读取：`版本 = 快照[阶段] ?? 最新[阶段] ?? 1`，缺失兜底到最新。

工作台落地最小形态：每词记一个 `planVersion: 1`，间隔表按版本查表。

## 6. 提醒时间计算（工作台 §7 通知）

```text
固定时刻（默认 20:00）：
  today = 今天的 20:00
  next  = now < today ? today : today + 1天
收藏复习提醒：以 next 为首日，连排未来 15 天同一时刻
```

自适应计算器是空壳（直接 fallback 固定时刻）——我们也先只做固定时刻。

## 7. 跟读流程引擎状态机（E4 句子跟读关的蓝本）

```text
Idle → PlayingPrompt(播原句) → Recording(录音)
     → [评测在引擎外，回调注入结果]
     → WaitingInterval(遍间倒计时) → 下一遍 / 下一句 / 完成
异常分支 → WaitingForUser(recordingFailed | userInteraction)
```

关键参数：

| 项 | 公式/值 |
| --- | --- |
| 录音上限 | `max(句长 × 2.5 + 5s, 10s)` |
| 智能遍间停顿 | `clamp(1000 + 0.6 × 句长ms, 2s, 20s)` |
| 固定停顿档 | 1/3/5/7/10…60s（默认 5s） |
| 每句遍数 | 3（难度表是占位，全档都 3；用户可改 1–10 或 ∞） |
| 倒计时快进 | 剩余时间压到约 1s 内走完 |

失败处理原则：播放/录音失败 → 停在 WaitingForUser 等用户，不静默跳过；**评分低不算失败**，照常推进；"再来一遍"允许超过目标遍数（如 4/3）。

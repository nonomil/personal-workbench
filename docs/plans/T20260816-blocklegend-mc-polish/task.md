## 2. 参考仓证据（tmp/voxel-refs/，已读源码）

### Fable5-mc（贴图与 AO 的主参考）

`src/textures.js`（核心画法，全部可用 16×16 Canvas 重写）：
- **草侧**：先画整格土，再画顶部 2–4px 锯齿草沿，草沿下一行压一条暗绿分界线。→ 直接替换我们「上 4 行平草」的呆板画法。
- **石头**：底噪 + 9 条 2–4px 横向暗纹 + 少量亮点。→ 替换纯噪点石头。
- **原木顶**：方形年轮（`max(|x-7.5|,|y-7.5|)` 取模交替亮暗）。→ 替换我们的圆形提亮。
- **原木侧**：按列整列明暗（竖条纹）+ 两侧边缘压暗列。→ 现状已接近，补边缘暗列。
- **树叶**：13% 像素打透明孔 + 18% 亮斑。→ 需要材质开 `alphaTest`（见风险）。
- **裂纹**：单独 crack 瓦片按破坏进度叠加。

`src/mesher.js`：
- `AO_CURVE = [0.45, 0.64, 0.82, 1.0]`：每顶点查 3 个邻格（两侧 + 对角），遮挡数映射暗度。
- **quad 翻转**：AO 对角差大时换三角形对角线，消除斜向漏光伪影。
- `FACE_SHADE = { px:0.6, nx:0.6, py:1.0, ny:0.5, pz:0.8, nz:0.8 }`：MC 原版面向亮度，比我们现值反差更大。

### dgreenheck/minecraft-threejs-clone（流式加载的主参考）

`scripts/world.js`：
- `drawDistance = 3`（区块半径）；玩家跨区块时：算出应在集合 → 新增的建、离开的 `disposeInstances` 卸。
- 玩家改动存 `dataStore`（我们已有 `world.edits`，语义相同，无需改）。

### twilson63/voxel

- 每类方块一张独立噪点 Canvas + InstancedMesh。画法与架构都不如现状，仅确认「我们没落后于它」。

## 3. 合入设计（每片独立可验，失败可单独回滚）

### S1 图集细化（只动 `makeBlockAtlas` + 常量）

- 图集扩到 4×5（64×80）或改 8×4，新增 4 格裂纹瓦片（25%/50%/75%/95%）。
- 移植画法：草侧锯齿边、石头横纹、原木方形年轮、原木侧边缘暗列、树叶孔洞（透明像素）。
- 地形材质加 `alphaTest: 0.5`（r147 Lambert 支持；不透明瓦片 alpha=255 不受影响）。
- 桦/杉沿用现有配色，只统一画法质量。

### S2 顶点 AO（只动 `buildChunkGeometry` / `pushQuad`）

- 对每面 4 顶点采样 side1/side2/corner 三邻格 `hasBlock`，映射 `AO_CURVE`，乘进现有顶点色。
- AO 对角差判断决定三角形对角线方向（quad 翻转）。
- `faceShade` 调整为 Fable5 数值（底面 0.5、南北 0.8、东西 0.6），整体反差立起来。
- 性能：AO 采样只发生在建网格/重建时，运行帧无成本；一次全图重建 25→（S4 后）≤25 个区块，可接受。

### S3 挖掘反馈（只动 `game.js` 挖掘路径 + 复用 S1 裂纹瓦片）

- `session.mine` 存在时，在目标块位置叠一个 1.002 倍透明盒，贴当前进度档裂纹瓦片（`polygonOffset` 防 z-fight）。
- 每 0.36s 挥动节拍出 2–3 粒目标块颜色碎屑（复用 `spawnBurst`，控制粒子预算）。
- 挖断/取消时移除遮罩。

### S4 区块流式（动 `engine.create` + 新增 tick 钩子）

- `WORLD_SIZE` 80→128；新增 `VIEW_CHUNKS = 3`（半径 3 → 最多 7×7=49 区块，但 128/16=8×8=64 全图，实际同屏 ≤49）。
- 启动只建出生点半径内区块；每帧预算最多建 1 个新区块（参考 Fable5 的 per-frame budget 思路）；离开半径的区块 `geometry.dispose()` + 移出场景，重进时重建（世界数据是纯函数 + edits，重建无损）。
- `remeshAt` 不变；小地图按 `world.size` 自适应（现有代码已按 size 缩放）。
- 雾距离配合调整，远处未加载区块藏在雾里。

### S5 收口

- 手玩走查（挖树、挖土、看 AO、看裂纹、跨区块走远）+ FPS 观察（MuMu 目标 ≥30）。
- test-report 记命令与退出码；设计文档 §世界、README「已可玩」行同步 128×128；总控登记。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| `alphaTest` 让树叶边缘锯齿明显 | 孔洞比例降到 8–10%；不行则树叶不打孔只保留亮斑（回退成本 1 行） |
| AO 让整体变暗 | AO 只乘侧/底面，顶面用 [0.6,0.8,0.92,1.0] 弱曲线 |
| 128 世界首屏建 ~25 区块可能卡 MuMu | 首屏只建 3×3，其余进逐帧队列；测 `engine.fps()` |
| 树体素查找是 O(trees)（`treeVoxelAt` 全树遍历），128 世界树更多、AO 采样次数更大 | S2 先给 `voxelAt` 加每列树体素缓存（Map 按 `x,z` 存该列树块），采样降为 O(1)；这是 S2 的第一步而非优化尾巴 |
| 世界变大后怪物/商人/花仍按旧坐标 | game.js 已用 `world.size` 派生（商人已改 mid 偏移）；走查确认刷怪半径 |

## 5. 明确不做

- 无限世界 / 存档流式（`edits` 已够）；水、火把、昼夜、生物群系；greedy meshing（合批面片已够 MuMu 预算）；替换角色盒子模型为贴图皮肤（另开任务）。

# 幼儿课程练习闭环设计

## 背景

当前幼儿版课程资源已经有识字、拼音、古诗、数学、专注力、英语和运动七个专区，也有本地课程完成记录；但练习卡点击后会直接完成，孩子看不到题目、示例或即时判断。下一轮重点是让“资源卡”变成真正可以做的一小步，同时保持阳光、豌豆能量、收集和家长备份的既有闭环。

## 设计目标

- 点击未完成练习后，打开一个适合幼儿阅读的大图练习面板。
- 每张练习至少包含题目、示例/提示和可操作的选项；答对后才能完成。
- 答错时只给提示，不扣阳光、不清空进度，也允许重新选择。
- 完成后复用现有 `courseProgress`、`lesson:<id>` 奖励事件和花园反馈，不新增第二套积分或任务账本。
- 首页显示一个“继续学习”入口，直接指向第一个未完成练习。
- 移动端面板可滚动、按钮至少 44px，支持键盘焦点和 `prefers-reduced-motion`。

## 交互流程

1. 课程卡上的未完成练习显示“开始练习”，已完成练习仍显示“已点亮”。
2. 点击未完成练习打开 `lesson-dialog`，展示课程名、题目、示例提示和选项。
3. 选择答案后立即显示“再想想”或“答对啦”；错误不会写入快照。
4. 答对后出现“收集阳光，完成练习”按钮；点击后才调用现有 `completeCourseLesson()`。
5. 完成提交后关闭面板、刷新课程进度、触发现有阳光/豌豆/收集反馈，并保留返回课程页的路由。

## 数据与边界

- 练习描述作为 `config.js` 中课程静态内容的 `activity` 字段，不进入 localStorage。
- 临时答题状态仅保存在 `app.js` 的内存 UI 状态，刷新或关闭面板即清除。
- 已完成 ID 仍只写入 `state.courseProgress.completedLessonIds`；奖励仍通过 `awardSunlight(next, \`lesson:${id}\`, 20)` 结算。
- 兼容没有 `activity` 字段的旧/自定义课程：使用 `meta` 和 `tip` 渲染“确认完成”模式，不阻塞旧快照恢复。
- 不修改自托管 API、SQLite 草案、Profile 隔离策略、Supabase 边界或现有花园状态结构。

## 视觉方向

- 沿用幼儿版暖奶油、橙色行动、薄荷绿色反馈和本地植物素材。
- 面板顶部使用当前课程图形，题目区域保持高对比、短句、大字号。
- 选项是带图形标记的宽按钮，不使用 Emoji 作为界面图标；内容文字由 HTML 渲染。
- 正确反馈使用现有庆祝层，错误反馈只在面板内显示，避免恐吓或惩罚性红色全屏提示。

## 验收标准

- 七个幼儿课程均至少有一个真实题目和三个可操作选项/状态选项。
- 未答题不能写入课程完成记录；答对并确认后只完成一次。
- 首页“继续学习”能跳到第一个未完成课程练习；没有未完成练习时显示完成状态。
- 桌面和 320/375/390/441px 移动视口无横向滚动，练习面板内容和操作按钮不被固定导航遮挡。
- `npm test`、语法检查、`git diff --check`、浏览器交互矩阵和 APK 安装启动检查全部通过。

# 花园保卫战 5×6 种植交互设计

## 目标

把幼儿版当前的“固定植物展示 + 单按钮技能”收敛成一块可操作的植物大战僵尸式草坪：植物卡片可以点击选中，也可以拖到 5×6 空草坪格种下；种植、技能、僵尸状态和阳光必须使用同一份本地持久化状态。

## 当前根因

1. `getDefenseView()` 会根据昨日漏打卡临时推导僵尸存在，但 `usePlantSkill()` 只读取持久化的 `garden.invader.active`，导致界面显示僵尸、结算却提示“先召唤一只僵尸”。
2. `renderPixelMap()` 中的五路植物是固定资产数组，不读取 `garden.defense.plants`，所以当前页面没有真实种植格。
3. `placeDefensePlant()` 已经有 5×6、阳光扣除、占位和解锁校验，但只被冻结的旧防守原型调用。
4. `animatePreschoolPea()` 的参数缺失，函数内部读取未定义的 `effect`，会在技能结算后产生运行时错误。

## 设计决策

### 1. 状态模型

- 继续使用 `growth.garden.defense` 作为唯一棋盘状态：`board.lanes = 5`、`board.columns = 6`、`plants` 保存 `{ id, plantId, lane, column, health, maxHealth, age }`。
- `garden.activePlantId` 表示当前选中的种子卡；`defense.selectedPlantId` 与它保持同步，兼容已有快照和旧原型调用。
- 种植成本读取 `DEFENSE_PLANT_RULES`，不再由页面单独维护另一份扣费规则。
- 保留现有“累计成长点解锁植物”规则；初始快照仍只开放向日葵，已有用户的解锁状态不回退。

### 2. 页面交互

- 种子卡：点击后只切换选中态、技能提示和当前种植类型，不立即发射或扣阳光。
- 空草坪格：点击即按当前选中卡种植；成功扣除阳光并在该格渲染对应植物。
- 拖动：种子卡使用原生 HTML Drag and Drop，拖入空格触发与点击相同的 `placeDefensePlant` 结算；点击是移动端和无拖动设备的降级入口。
- 已占用格：不覆盖、不扣费，给出明确提示；植物不会因为切换卡片而被替换。
- 技能：技能按钮只调用当前选中植物的专属技能。坚果墙不会走豌豆发射动画；没有对应已种植物时提示先种下该植物。

### 3. 战斗语义

- 先修正“临时僵尸视图”和技能结算的数据边界：技能操作前把同一日期下的可见僵尸状态纳入结算输入，避免 UI 与规则分裂。
- 保留当前单只僵尸的轻量手动练习闭环，不在本轮恢复旧原型的自动计时循环。
- 统一技能动画参数；豌豆、冰豌豆、樱桃爆炸和坚果阻挡使用各自效果类，坚果不创建 `pixel-pea-projectile`。
- 僵尸被击倒后沿用现有短暂倒下状态和 DOM 移除逻辑。

### 4. 错误与兼容

- 规则层返回 `{ ok, growth, reason }`，位置非法、已占用、未解锁、阳光不足都不能改变状态。
- 新字段沿用 `normalize()` 的默认值和旧快照迁移，不清理已有 `garden.defense`、解锁或完成状态。
- 当前首页仍只展示轻量概览；只有“花园保卫战”页面读取和操作棋盘。

## 验收标准

1. 点击豌豆射手/坚果墙卡片后，选中态与技能文案同步改变。
2. 初始可用向日葵能在任意空格点击或拖放种植；阳光减少一次，刷新后位置仍在。
3. 已占用格、未解锁植物和阳光不足均有可见提示且不改变棋盘。
4. 选中坚果墙时技能效果为阻挡，不扣豌豆能量、不创建豌豆动画；选中豌豆射手时才发射豌豆。
5. 漏打卡自动出现的僵尸也可以被技能正常结算。
6. 现有测试全部通过，并新增规则层与页面契约测试覆盖上述行为。

## 1. 设计结论

采用“轻量工作台 + 独立花园游戏 + 发布门禁”三层结构：

```text
今日工作台
  ├─ 今日可编辑计划
  ├─ 直接打卡 / 同级轻量练习
  ├─ 完成证据、阳光、成长、连续行动
  └─ 去花园游戏 / 去奖励中心

资料库
  └─ 60 日自然拼读、暑假学习单和各科资料，只作为内容来源

独立花园游戏
  └─ 植物选择、放置、技能、僵尸波次和动画，不修改学习完成状态
```

工作台不继续扩张为完整课程平台，也不把首页改成植物大战僵尸完整复刻。参考案例中真正值得迁移的是“专属伙伴 → 今日行动 → 可见证据 → 即时奖励 → 下一步/游戏出口”的短闭环。

## 3. v0.5.0 用户路径

### 3.1 首页

首页保留四层：

1. 身份层：伙伴、等级、阳光、连续行动、豌豆能量和下一步。
2. 行动层：六条可编辑计划战线；每条计划可直接打卡，有映射时显示同级“去练习”。
3. 证据层：今日完成数、练习证据数量、阅读记录摘要和下一张学习卡。
4. 出口层：花园保卫战、奖励中心、成长页和学习专区。

练习按钮与打卡按钮必须是同级 DOM 操作，禁止嵌套 `<button>`。已完成计划不显示“去练习”。

### 3.2 轻量练习

- 练习沿用现有 `childCourses` 和 `lesson-dialog`，每次只处理一张选择题卡。
- 英语自然拼读作为英语专区的一部分，不把 60 日资料直接变成首页课程列表。
- 练习答对后显示结果、阳光和豌豆能量反馈，并同步来源计划。
- 从课程专区独立完成课程卡时，仍使用原有课程进度和幂等奖励；从计划进入时额外携带来源计划上下文。

## 4. 数据合同与幂等规则

幼儿 `dailyPlans` 保留现有字段，并增加：

```js
{
  id,
  date,
  title,
  category,
  required,
  practiceLessonId,
  done,
  completedAt,
  completionSource,
  completionRewardId
}
```

`completionRewardId` 是一次计划完成奖励的稳定凭证：

- 直接打卡首次完成：`plan:<planId>:<date>`，奖励 10 阳光。
- 从计划进入练习并完成：`lesson:<lessonId>`，奖励 20 阳光；不再追加计划 10 阳光。
- 计划取消时保留 `completionRewardId`，再次完成不能重新发放同一计划奖励。
- 如果已直接打卡再进入练习，课程卡可以完成，但来源计划不再重复领取计划奖励；如果课程卡已经完成，计划入口仍能把计划同步为已完成而不抛出误导性错误。
- 所有实际落值仍必须经过现有 `recordAction()` / `awardSunlight()`，不新增积分账本。

迁移规则：

- 旧快照没有 `practiceLessonId` 时，只给内置模板补映射。
- 旧快照没有 `completionRewardId` 时，默认为空；第一次取消旧完成项时写入保护凭证，避免之后重复奖励。
- 不覆盖用户改名、删除、自定义计划、完成状态和已有课程进度。

## 6. 验收门禁

### 数据与代码

- 旧三项快照迁移到六项计划不丢完成状态、改名或自定义项。
- 练习完成后计划同步，刷新后仍保持。
- 练习 → 取消 → 直接打卡、直接打卡 → 取消 → 再打卡、直接打卡 → 练习三条路径都不重复发放同一计划奖励。
- `node --check app.js`、`node --check storage.js`、`git diff --check` 通过。

### 浏览器

- 首页显示六条可编辑任务战线和同级练习入口。
- 英语练习答题、领取、返回首页、刷新完整闭环可见。
- 390px 竖屏无横向滚动，侧栏手动开合；横屏侧栏保持显示。
- 运行日志无错误，首页不出现战斗棋盘。

### 发布

- `npm test` 和幼儿专项测试全绿。
- 运行 Pages 制品组装/门禁（若仓库当前发布脚本存在）。
- 运行 `npm run android:prepare` 与 `npm run android:build`，产生可下载 Debug APK；不把 Debug 包表述为签名商店包。
- 推送 `main` 后检查 GitHub Actions 结果；下载 APK 后用 MuMu 验证启动、三入口切换、幼儿练习、花园入口和本地刷新保持。
- 只有上述证据齐全后，才创建 `v0.5.0` 标签和发布说明。

## 7. 风险与停止点

- 如果奖励跨路径合同无法在现有快照模型中稳定实现，停在数据层，不继续扩展课程或游戏。
- 如果 GitHub Actions 或 MuMu 环境失败，只记录精确命令、日志和产物状态，不把网页测试升级为 APK 发布成功。
- 不删除现有 `.worktrees`、历史资料或未提交用户改动。

# 植物僵尸工作台沉浸式改版实施计划

> 给 Codex：执行本计划前先读取本文件、现有源头方案和 T20260827-scene-immersion 任务包。后续实现必须按 S1→S5 顺序进行；本轮只产出方案文档，不修改代码、不生成新素材、不执行测试。

**目标：** 把植物僵尸工作台从“学习卡片堆在页面里”升级为“上方稳定学习卡片、下方动画人物舞台、背景提供花园氛围”的儿童学习工作台，让人物既是陪伴者，也是栏目入口和答题反馈者。

**技术栈：** 现有原生 HTML、CSS、JavaScript、Capacitor Android 壳、现有 preschool 主题资产；不增加动画库、状态库、字体网络请求或 storage key。

### 1.1 对参考文档的正确解读

外部文档展示的是一个以兴趣驱动启蒙学习的产品样本。它的价值在于信息架构和情绪设计，而不是“布鲁伊主题”这四个字本身：

- 首页用左侧栏目让家长知道有哪些入口，用中上部的一张卡告诉孩子现在该做什么，再用场景人物让页面有陪伴感。
- 人物头顶的气泡把“栏目名称”和“下一步行动”变成可读提示，减少孩子寻找按钮的成本。
- 识字、英语、国学、亲子游戏等页面共用一个工作台外壳，但主卡随学习任务改变。
- 奖励页把获得的币、宠物状态、可兑换物和已收集物件放在同一空间里，形成“学习—获得—看得见”的闭环。
- 页面转场和动画片入口是增强项，不是植物僵尸工作台本轮的基础能力。

因此，本项目应使用已有 PVZ 花园、方块、闯关三套素材和现有本地数据，做“同一产品机制的主题化表达”，而不是做布鲁伊复制品。

## 2. 参考图逐项分析与产品取舍

### 2.1 首页：frame_1.jpg

观察：

- 左侧是固定的栏目导航，栏目有色彩区分，并且每个栏目带有角色图。
- 右侧上方是问候、日期、每日金句和连续打卡信息。
- 中间大面积是一个可辨识的家庭/花园场景，角色分散在不同位置。
- 角色上方有气泡，气泡直接说“识字计划开始”“通识学习真有趣”等。
- 右下角保留货币/奖励状态。

采用：

- 保留左侧导航和右侧主内容的方向。
- 首页只保留一张明确的“现在做什么”主卡，避免多个任务卡同时争夺注意力。
- 将气泡和角色改为 PVZ 植物伙伴，气泡显示栏目名或下一步，而不是装饰性台词。
- 让太阳、云、草地成为低频背景动效，人物成为低幅度前景动效。

不采用：

- 不在第一屏同时展示八个大入口和很多漂浮气泡。
- 不让场景人物覆盖学习卡的文字或点击区域。
- 不引入参考图里的外部网站或动画片跳转作为默认行为。

### 2.2 识字页：用户附带 PNG 与 frame_3.jpg

观察：

- 参考识字页的中心是一个大字和写字区域，右侧是“今天要认识的字”列表。
- 用户附图中也有左侧导航、树木背景、中心大字/田字格和右侧字表，但背景人物和内容卡的视觉权重接近，阅读焦点不够稳定。
- 识字任务既包含“看字、听字、组词”，也包含“写一写”和“标记会了/还不会”。

采用：

- 内容卡始终位于主要阅读层，背景只提供颜色和空间，不抢文字对比度。
- 识字页顶部只保留课程标题、返回和进度；不要再堆叠多层标题盒。
- 主学习区以一个当前字或一组当前卡为中心；字卡队列是辅助，不成为第二个大主角。
- 底部用矮场景条承载三名学习伙伴；角色可以微动和回应，但不能让田字格一起晃动。

不采用：

- 不把整幅背景图当作内容卡的底色，导致字、笔顺和人物重叠。
- 不把第一次点击“看提示”误判成答错。
- 不用红色叉号、红色大面积警报给幼儿制造失败压力。

### 2.3 亲子游戏页：frame_5.jpg

观察：

- 页面以一张活动说明卡为中心，背景是可活动的生活场景。
- 说明卡包含准备物品、时间、人数和安全提示。
- 下方人物展示正在做的动作，场景本身强化“现在要一起做”。

采用：

- 对每日运动、亲子活动使用“活动主卡 + 场景人物”的模板。
- 把安全提示留在主卡内，不因动画而隐藏。
- 角色的动作反馈只在点击开始、完成或打卡时触发。

不采用：

- 不把亲子游戏直接混进识字卡墙。
- 不让走动人物成为需要点击才能读懂的唯一说明。

### 2.4 英语页：frame_6.jpg

观察：

- 页面中心是一个词、插图和跟读提示。
- 动画片/媒体推荐位于学习内容之外，是可选的兴趣入口。
- 参考画面有较多生活场景和角色，但“Friend”等学习词仍然是明确焦点。

采用：

- 英语页保持“大词/大图/听读/例句”的单主卡。
- 媒体推荐继续放入现有课程 tab 或媒体入口，不自动播放。
- 豌豆伙伴可以承担“跟我读”的情绪角色，但不替代发音内容。

不采用：

- 不把外部视频站点作为本轮必需依赖。
- 不为了匹配参考图而新增网络媒体存储或远程字体。

### 2.5 页面转场：frame_14.jpg

观察：

- 画面用翻页/擦除式转场表现从英语到国学或其他栏目切换。
- 这是演示视频中的氛围增强，不是信息架构本身。

取舍：

- P0 不实现整页转场。
- 角色点击只做 450–600ms 的轻量跳起、气泡变化，然后进入新路由。
- 如果以后要实现转场，必须独立验证低端 Android WebView 性能，并且不能阻塞路由。

### 2.6 奖励页：frame_29.jpg

观察：

- 左侧显示当前宠物状态和喂养按钮，右侧是有展示架/商店感的奖励区域。
- 货币余额、宠物状态、消费物品和收集物件同时可见。
- “吃饱了”之类的短反馈让兑换行为立即得到回应。

采用：

- 奖励页第一屏把下一站进度和宠物/植物舞台放在一起。
- 收集品以架子或花园摆件呈现，解锁以后“空间里多了一件东西”。
- 喂食、浇水、抚摸等行为复用现有动作和成长状态，不重新设计一套宠物数据。

不采用：

- 不把现实奖励兑换流程改成自动领取。
- 不新增拖拽摆放、交易、联网商城或家长确认逻辑。

### 2.7 其他工作台横向审阅：问题不是“没有设计”，而是目标密度不一致

本轮同时抽样审阅了 `G:\UserCode\跨平台采集器\notes\游戏化学习工作台` 下的其他工作台。它们大多面向家长管理、任务总览或较大桌面视口，不能直接作为 3 岁孩子 Android 横屏首页的尺寸模板。

| 参考工作台 | 值得保留的机制 | 造成“太大/太满”的做法 | 对植物僵尸工作台的转译 |
| --- | --- | --- | --- |
| 马里奥幼小衔接学习台 | 主任务、宠物和奖励反馈直观 | 红色侧栏、英雄卡、状态数字、多个按钮都以“大组件”出现 | 保留“现在做什么 + 伙伴反馈”，把状态压成一条轻量栏，首屏只留一个主 CTA |
| 幼小衔接 APP | 课程分组和学习目标容易理解 | 两列大课程卡在窄屏占据过多纵向空间 | 改为一张当前主卡 + 紧凑的今日队列，其他课程进入课程墙/第二屏 |
| 暑期作业台 2.0 | 任务分组、必做/选做关系清楚 | 暗色遮罩、加载反馈和后台控件让孩子等待并阻塞内容 | 保留任务分组；反馈改为卡片内短状态，不能遮住主卡和角色 |
| Minecraft 学习工作台 | 主题、任务、宠物、战斗、商店、小游戏一致；底部 Tab 适合移动端 | 一次展示大量作业，首页变成长列表 | 保留主题闭环和底部入口；首页只呈现今天的一步，完整任务移入分页 |
| 游戏化学习冒险基地 | 日历、任务、成长地图、伙伴、档案闭环完整 | 三列、多个指标、日历和任务同时出现，偏家长后台 | 把成长数据保留给家长/第二层；孩子第一屏只看主任务、伙伴和下一步 |
| “什么是真正的工作台”原则稿 | 强调真实学习、真实完成、真实奖励数据 | 反对把打卡/勾选数量当成学习本身 | 所有视觉简化都不能删除真实记录；不生成虚假 streak、阳光或完成数 |

横向审阅的结论不是“所有组件都要缩小”，而是重新分配视觉权重：

1. 家长需要的全量信息可以继续存在，但不能和孩子当前要做的动作处在同一层级。
2. 伙伴、奖励和背景负责让孩子愿意留下来；汉字、题目、听读和写字负责让孩子完成学习，二者不能争夺同一个焦点。
3. 一张卡只回答一个问题：现在做什么、做完会得到什么，或下一步去哪里。不要在一张卡里同时放任务管理、成长统计、奖励兑换和世界入口。
4. “游戏化”应当来自真实行为的可见反馈，而不是把每个状态都包装成大卡片。

### 2.8 当前“太大”的根因与反模式

以下判断用于指导后续改版，不等同于要求删除已有功能：

| 根因 | 画面表现 | 修正规则 |
| --- | --- | --- |
| 每个模块都被当成主角 | 主任务、英雄图、字表、伙伴、积分卡同时放大 | 固定主次：学习主卡 > 主 CTA > 伙伴舞台 > 状态信息 > 次级入口 |
| 用卡片承载所有状态 | 日期、连续天数、阳光、任务数各自占一块大面板 | 状态合并到一条状态栏；只有当前任务和当前奖励保留独立卡面 |
| 按桌面宽度设计后直接压到横屏 | 800×360 时标题、内边距、按钮和角色互相挤压 | 先以 800×360 建立预算，再向 1463×616 放大留白，不增加信息数量 |
| 角色尺寸按“好看”而非“陪伴”决定 | 植物图片占满内容区，人物遮住字卡或按钮 | 角色脚底落在矮舞台，图片可以醒目但舞台高度受控，命中区独立 |
| 重要和次要动作同样醒目 | 去学习、查看全部、管理、兑换、进入游戏都使用同等级按钮 | 每屏一个主 CTA；次级动作使用文字链接、分页或折叠入口 |
| 首屏一次展示全部内容 | 任务、错题、世界、奖励和课程墙一起出现 | 使用“第一屏做一步、第二屏看全部、第三屏去世界”的渐进披露 |
| 过度依赖装饰动效 | 卡片、数字、背景、人物都持续变化 | 卡片稳定，只有背景低频动、角色待机/回应动；默认同时动效不超过预算 |

### 2.9 低密度 UI 规范：以 800×360 为硬约束

下面是设计和实现共同遵守的尺寸预算。它们是布局边界，不要求把每个数字写成不可调的固定像素值；出现内容冲突时，优先缩减装饰和次级信息，不压缩字、题目和主 CTA 的可用性。

| 项目 | 800×360 Android 横屏 | 1463×616 宽横屏 | 设计意图 |
| --- | ---: | ---: | --- |
| 顶部状态区 | 约 32–36px | 约 44–52px | 一行完成问候、进度、阳光和设置，不再拆成多张状态卡 |
| 首页主舞台 | 约 86–100px | 约 120–150px | 伙伴在下方有生命感，但不能抢走主卡高度 |
| 学习页矮场景条 | 约 48–64px | 约 64–84px | 只承载伙伴和反馈气泡，不承载第二套学习内容 |
| 同屏伙伴 | 最多 3 个；不常驻第四个挑战角色 | 最多 3 个，挑战角色仅在空间足够时作为弱化入口 | 角色是陪伴/导航，不做角色图鉴墙 |
| 主 CTA | 1 个 | 1 个 | 让孩子不需要比较多个“开始”按钮 |
| 关键数字 | 最多 4 个 | 最多 4 个 | 只显示完成数、阳光/奖励等真正影响下一步的数字 |
| 学习辅助卡 | 主卡外最多 4 张 | 可增加留白，不增加信息种类 | 其他内容进入分页、折叠或课程墙 |
| 触摸命中区 | 不小于 44×44px，角色建议 48×48px | 不小于 44×44px | 视觉可以缩小，交互命中区不能缩小到难以点击 |

尺寸执行顺序：

1. 先锁定顶部、主卡、场景条和按钮的最小可用高度，再放背景和角色。
2. 先保证汉字/题目/选项的阅读和点击，再决定角色图能放大多少。
3. 宽屏只增加呼吸感、背景层次和角色移动距离，不增加首页卡片数量、数字数量或主 CTA 数量。
4. 任何新组件都必须回答“它是否帮助孩子完成当前一步”；不能回答时放到第二屏或家长区域。

### 3.1 当前体验问题

1. 首页虽然已有场景、任务和伙伴，但第一屏的信息层次仍然偏“管理面板”：任务泳道、伙伴条、世界出口都在争夺空间。
2. 背景场景目前主要是静态装饰，角色没有成为清晰的导航入口。
3. 识字页的内容模型已经具备大字、田字格、卡墙和底部伙伴，但需要让卡片稳定、人物动起来，不能反过来让内容跟着场景漂移。
4. 场景条的三个按钮当前都指向 growth，用户点击角色无法进入它所代表的栏目。
5. 答题判定分散在多个分支；直接在单个分支里复制欢呼逻辑容易漏掉课程模式、重复触发或破坏原有记账。
6. 奖励页已经有真实奖励、收集和成长数据，适合做舞台化展示，但喂养动作在 rewards 页是否已有可复用入口需要在 S5 前确认。

## 4. 产品总原则

### 4.1 儿童认知层级

- 一屏只保留一个主任务：现在认什么、读什么、算什么或做什么。
- 内容卡比背景更稳定、更亮、更易读；场景人物只做陪伴、提示和反馈。
- 卡片点击进入渐进披露：先看到大字/大词/大题，点卡后再显示组词、解释或细节。
- 一次最多 4 张可点辅助卡，或 1 张主卡；每张卡不超过 2 个主要操作。
- 文案短、动词先行：去学习、听一听、写好了、再看一遍、去领奖励。

### 4.2 PVZ 视觉继承

现有花园主题 CSS 变量已提供基础色板：

- 深墨蓝：#24435a，用于正文和高对比文字。
- 草叶绿：#52b66f，用于成长、成功、草地和状态。
- 阳光黄：#ffd766，用于奖励、可行动状态和光粒子。
- 天空蓝：#6fc9f7，用于背景和学习入口。
- 珊瑚色：#f38d76，用于少量强调，不用作错误警报。
- 奶油白：#fff9e9，用于内容卡和纸张感表面。

方块和闯关主题可替换背景、资产和强调色，但信息结构、文字对比度、点击反馈和动效开关必须一致。不要为了追求“像参考图”而改成布鲁伊的蓝橙配色。

### 4.3 场景三层构图

从下到上固定为：

| 层 | 责任 | 可动内容 | 禁止内容 |
| --- | --- | --- | --- |
| 背景层 | 天空、已有主题背景、太阳、云、远景地面 | 低频 translate/opacity | 不承载按钮、不覆盖正文 |
| 学习内容层 | 标题、主卡、田字格、题目、选项、进度 | 只有一次性状态反馈时可改变 opacity | 不做循环位移、不随角色移动 |
| 人物舞台层 | 伙伴、角色气泡、草地前景、奖励宠物 | 待机、跳起、走动、欢呼、安慰 | 不挡住主卡、不把角色当唯一文字说明 |

建议层级关系：

- scene 背景低于 main-content。
- 主卡和学习按钮高于角色舞台的装饰部分。
- 角色命中区只在其舞台容器内可点击，舞台外不扩大点击范围。
- 气泡可以浮在角色上方，但不能溢出页面或遮挡标题。

## 6. 首页详细设计：今天先做一件事

### 6.1 Android 横屏第一屏

目标画面：孩子打开工作台后，在 3 秒内知道“现在做什么”，并且在 1 次点击内进入课程。

    ┌─────────────────────────────────────────────────────────┐
    │ 左侧固定导航 │ 问候 / 日期 / 阳光 / 能量 / 设置          │
    ├──────────────┼──────────────────────────────────────────┤
    │              │ [现在就做] 识字/拼音/数学主任务卡           │
    │              │ 标题 + 一句鼓励 + 一个“去学习”按钮         │
    │              │                                          │
    │              │            ☁       ☀       ☁              │
    │              │        ───────  花园背景  ───────           │
    │              │        向日葵   豌豆   坚果   小僵尸         │
    │              │          气泡：点我进入对应栏目             │
    │              │                         [分页器]           │
    └──────────────┴──────────────────────────────────────────┘

布局规则：

- 现有 home-primary 仍是第一页的语义容器；只把场景舞台追加到它内部或其明确的主页面包裹层。
- 800×360 目标下，顶部状态区约 32–36px，主卡占内容区的主要高度，舞台约 86–100px；不要让角色挤压主卡按钮。
- 1463×616 目标下，舞台可扩大到约 120–150px，并显示更完整的背景和角色动作。
- 左侧导航保持可识别；如果 Android 横屏可用宽度变窄，只压缩导航文案和角色图，不把主卡缩到不可读。
- 太阳和云可以贯穿右侧背景，但不能改变主卡的对比度。

首页密度验收：

- 第一屏只出现一张主任务卡、一个主 CTA 和一个伙伴舞台；任务泳道、错题回流、世界入口不与它们争夺首屏主层级。
- 800×360 同屏最多 3 个伙伴和 4 个关键数字；小僵尸挑战入口如果无法保持低干扰，就放到第三屏。
- 1463×616 可以放大舞台和留白，但不得因为空间变大而重新塞回完整任务列表或更多大卡。

### 6.2 顶部问候与状态

保留现有 header 的功能：

- Hi，小探险家和日期。
- 今日完成数，例如 1/3 项已完成。
- 阳光余额、主题能量和设置入口。

视觉上把它压成一条轻量状态栏，避免出现多个大卡。每日金句可保留一行，不应占据比主任务标题更大的视觉权重。

### 6.3 “现在就做”主卡

数据来源和行为：

1. 优先使用现有 getPreschoolHomeWorkflow(plans) 或等价的当前 workflow 结果。
2. 选择第一条未完成且有学习课程的任务；不要在首页重新实现一套任务排序。
3. 若任务有 courseId，复用 open-plan-course 行为进入现有课程。
4. 若任务没有课程，保留现有 toggle-plan 或管理任务行为，显示“完成这一步”而不是伪造课程入口。
5. 今天全部完成时，主卡显示“今天的花园点亮啦”，按钮进入 rewards 或现有奖励入口。

主卡字段：

- 小标签：现在就做、下一步或今天。
- 主标题：任务标题，最多两行。
- 辅助语：课程描述或“答对后留下练习证据”。
- 主要按钮：去学习、去完成、去领奖励三者之一。
- 可选一行证据：已完成的最近练习，不再额外生成第二个大卡。

### 6.4 首页舞台

舞台由四个区域组成：

- 天空/背景：复用 child-game-scene 和当前主题背景。
- 低频环境动效：太阳、两朵云、草地前景。
- 角色：三个学习伙伴；大舞台可以加一个挑战角色。
- 气泡：默认展示栏目或当前任务，点击后短暂显示行动文案。

角色摆位：

- 角色脚底都落在同一条草地基线，不要出现漂浮。
- 角色之间保留至少一个角色命中区的宽度。
- 走动角色只在舞台内部移动，容器 overflow hidden。
- 角色 art 可比文字大，但可访问名称必须由按钮 aria-label 提供。

### 6.5 首页第二、三屏

第一页减负不等于删除功能：

- 第二屏保留完整任务泳道、必做/选做统计、错题回流和管理任务。
- 第三屏保留主题世界入口、世界游戏和家园入口。
- 分页器标签使用“现在就做”“今天的任务”“我的家园”，而不是只显示数字。
- 既有任务、错题回流和世界出口的 action 不改名、不改数据来源。

### 6.6 非 Android 横屏

- 竖屏仍然保持可滚动，先不强行套用横屏分页器。
- 桌面网页可以使用相同的三层视觉语言，但不得因为本任务改变当前桌面信息流和侧栏行为。
- 只有在 800×360 和 1463×616 验收通过后，才考虑把大舞台扩展到其他断点。

## 7. 识字与学习内容页详细设计

### 7.1 通用学习模板

    ┌─────────────────────────────────────────────────────────┐
    │ 返回 │ 学科标题 │ 今日进度                         翻页 │
    ├─────────────────────────────────────────────────────────┤
    │                                                         │
    │               一张稳定的主学习卡                         │
    │       大字/大词/算式/诗句 + 必要解释                      │
    │       听一听 / 写一写 / 选答案等最多两个主操作             │
    │                                                         │
    │       可选：2–4 张辅助卡或一组紧凑的今日队列               │
    ├─────────────────────────────────────────────────────────┤
    │ 场景条：进度语气泡       向日葵  豌豆  坚果               │
    └─────────────────────────────────────────────────────────┘

规则：

- 主卡区稳定，循环动画只出现在底部场景条。
- 在 800×360 下，场景条约 48–64px；不能占掉田字格和按钮的最小高度。
- 在高分横屏中可扩大伙伴图，但不把场景条变成第二个课程卡墙。
- 内容超出时允许页面级纵向滚动兜底，不能用 fixed 高度裁掉字卡和安全提示。
- 课程切换仍然通过 setPage(courses, courseId, courseTab)。

学习页密度契约：

- 汉字、单词、算式或诗句是唯一认知主角；背景、伙伴和奖励提示的对比度必须低于主学习内容。
- 首屏只保留一个主学习卡和最多两个主要操作；“看提示/再听一遍”等辅助操作不应再生成一张等大的并列卡。
- 800×360 下优先保留主内容、听读/作答按钮和必要进度；今日队列可以缩为横向小卡或放到页面下方，不能和主卡五五分屏。
- 角色气泡最多显示一条短句，且不遮住字、田字格、题目、选项或安全提示；气泡过长时截断或换成短文案。
- 任何循环动效都不能改变主卡的尺寸、位置或文字布局；答题反馈结束后应自动清理临时 class 和粒子。

### 7.2 识字页

主任务顺序：

1. 看见一个足够大的汉字。
2. 看拼音和一个简短的组词/含义。
3. 点听一听或在田字格写一写。
4. 需要时点卡展开提示。
5. 只有真实标记或真实答题以后，才进入会了/还不会的反馈。

推荐结构：

- 顶部：识字专区、返回、今日已点亮数量。
- 左/中主区：当前字、拼音、笔画/组词提示、写字区域。
- 右/下辅助区：今日字卡队列，展示未完成、已点亮和复习标记。
- 底部：花园学习伙伴场景条。

关键交互语义：

- flashcard-reveal 只负责显示提示。
- 未展开字卡第一次点“还不会”时，只展开提示并 render，不派发错误反馈。
- 已展开后再次点“还不会”，或在真实 lesson-answer 中答错，才进入安慰状态和复习记录。
- markedCount 在渲染阶段从 session.items 和 session.marks 计算，并显示为“已点亮 / 总数”。

### 7.3 拼音页

- 主卡显示声母/韵母或当前音节，字号高于说明文字。
- 首要操作是听音和拼读；选项题保留足够大的命中区。
- 答对时豌豆伙伴点头或跳起；答错时只给温和提示，不让整张卡变红。
- 伙伴点击直接进入 preschool-pinyin，不跳到 growth。

### 7.4 英语页

- 主卡显示单词、插图、中文提示和例句中的一个重点。
- 听读优先；媒体推荐是可选 tab，不自动播放。
- 可使用“跟我读”“再听一遍”等短文案。
- 课程墙继续保留 preschool-english 和 preschool-minecraft 的现有入口，不因角色映射而删除。

### 7.5 数学页

- 主卡只呈现一个算式或一个口算任务。
- 选项按钮保持独立、可读、可触摸；不要把动画放在算式或选项本体上。
- flashcard-math-pick 是独立答题入口，S1 统一反馈协议必须单独审计它。
- 坚果伙伴可以做小幅呼吸或滚动反馈，但不能在错误时模拟受到伤害。

### 7.6 古诗、运动和其他内容

- 古诗：诗句主卡 + 朗读 + 解释/关键词；可用背景场景，但诗句永远是最高对比层。

## 8. 人物导航、气泡和答题反馈

### 8.1 角色状态机

| 状态 | 触发 | 视觉结果 | 时长/结束 |
| --- | --- | --- | --- |
| idle | 页面稳定 | 小幅呼吸、摇摆或点头 | 循环；仅舞台角色 |
| speaking | 气泡轮换或当前指向 | 角色高亮，气泡显示栏目名 | 约 2–4 秒 |
| pressed | 点击角色 | 角色跳起，按钮有 active/focus 反馈 | 450ms 左右 |
| navigate | pressed 完成 | 调用既有 setPage | 600ms 内；no-motion 立即 |
| cheer | 答对 | 三个角色依次跳起，气泡夸奖 | 450–900ms |
| comfort | 答错/真实不会 | 坚果或当前安慰角色轻轻摇摆，显示安慰语 | 600–900ms |
| sunrain | 连对三题 | 最多 6 个阳光粒子从舞台上方落下 | 2 秒后移除 |
| walk | 首页大舞台闲置 | 角色在草地范围内往返、朝向翻转、轻微颠簸 | 12–20 秒循环 |
| reward | 喂养/领取成功 | 宠物跳起或收集物点亮 | 一次性；不改变账本语义 |

### 8.2 点击人物的行为契约

每个角色按钮应输出：

- data-action=navigate。
- data-page=courses 或 battle。
- 课程角色额外带 data-course-id。
- aria-label 为“角色名，去栏目名”。
- 视觉图的 alt 可以为空，因为按钮已有完整可访问名称。

点击顺序：

1. 加入 is-clicked 或等价状态 class。
2. 气泡立刻点名目标栏目。
3. 动效开启时等待不超过 600ms。
4. 调用既有 setPage，不修改路由函数。
5. 期间阻止同一角色重复点击，完成或取消时恢复 pointer-events。
6. preschool-no-motion 下跳过等待，仍然执行路由。

### 8.3 答题反馈统一事件

建议使用一个内部 helper 统一发出：

    preschool:answer

事件 detail 至少包含：

- correct：本次真实答题是否正确；自评卡可用 known 语义映射。
- streak：当前内存中的连续答对次数。
- source：flashcard-mark、lesson-answer、math-pick 等来源。
- courseId：当前课程 ID。

派发边界：

- flashcard-reveal 不派发。
- markPreschoolFlashcard 在首次未展开“还不会”时不派发。
- answerLesson 的 assess、drill、literacy run/loop、bankQuiz 和普通 choice 分支都要经过统一 helper；不能只覆盖当前最容易看到的一个分支。
- flashcard-math-pick、英语 quiz 确认等独立答题动作是否接入，须在 S1 测试矩阵中明确写出；未接入前不能在验收中声称“所有学科都有反馈”。
- streak 只保存在当前内存，不写入 storage；切换课程、离开学习页或刷新后可以重置。

反馈文案示例：

- 答对：太棒啦、找对啦、再来一个、阳光收到了。
- 答错/真实不会：没关系，再看一遍、慢慢来、提示就在这里、你已经很勇敢。
- 完成：这一页完成啦、今天的字卡点亮了、下一格等你。

## 9. 动画技术方案与性能预算

### 9.1 红线

1. 循环或一次性动画只改变 transform 和 opacity。
2. 不动画 box-shadow、top、left、width、height、margin 或 layout 属性。
3. CSS keyframes 负责动画，JavaScript 只负责切换 class、状态和事件。
4. 卡片、汉字、算式、选项不做循环动画。
5. 每屏常驻动画元素不超过 8 个；阳光雨/爱心等一次性粒子不超过 6 个。
6. 不使用 :has()、color-mix() 或没有 vh 回退的裸 dvh/svh 规则。
7. 保留现有 vh 后接 dvh 的兼容写法；不在本任务中批量重写历史 CSS。
8. 不新增 storage key、运行时网络请求或 JavaScript 动画依赖。

### 9.2 现有 transform 冲突处理

当前伙伴已经有 learning-companion-sway。走动、呼吸、翻转和点击如果同时写在同一个元素上，会互相覆盖 transform。建议固定职责：

- 外层 preschool-learning-companion：负责大舞台的 translateX 走动或点击暂停。
- 中层 preschool-learning-companion-art：负责轻微上下颠簸。
- 内层图片：负责 scaleX(-1) 朝向翻转或既有 sway；不要在同一节点叠加两个 transform keyframe。
- 点击跳起时暂停 walk；完成后恢复 idle。
- 学习页矮场景条不启用走动，只保留低幅度待机和一次性反馈。

### 9.3 动画元素预算

| 页面 | 常驻动画 | 预算核对 |
| --- | --- | --- |
| 首页大舞台 | 两个走动角色 + 两个颠簸内层 + 太阳 + 两朵云 | 7，第三个角色保持静态或仅复用其中一个待机槽 |
| 识字/学习页 | 三个伙伴的低幅度待机；无走动 | 3；答题反馈是短时状态，不与走动叠加 |
| 识字阳光雨 | 上述待机 + 最多 6 个粒子，粒子 2 秒后移除 | 粒子有独立上限，不产生真实阳光 |
| 奖励页 | 一个宠物待机；喂养成功最多 3 个爱心 | 常驻 1，一次性粒子 3 |

### 9.4 背景动画

- 太阳：4 秒 scale 往返；光芒如需旋转，优先使用一个伪元素，避免拆成多层。
- 云 A/B：分别以约 60 秒和 90 秒做横向 translate，透明度保持低。
- 草地：一条前景条做 6 秒轻微 translateX，不让每根草各自动画。
- no-motion 和 prefers-reduced-motion 下全部停止，保留静态背景和可读文字。

## 11. 无障碍、触摸和家长控制

- 每个角色按钮的有效命中区至少 48×48px；视觉角色可以更大，但不要让图片本身决定可点击范围。
- 气泡和辅助文字最低 12px；正文、按钮和高频提示达到可读对比度。
- 不依赖 hover；必须有 focus-visible、active 和点击后的明确状态。
- 颜色不是唯一反馈：答对同时使用气泡、角色动作或文字；答错使用安慰文案。
- 关闭动效后，按钮、文案、路由、学习记录和奖励记录仍完全可用。
- 语音/音乐继续遵守现有默认关闭或用户选择；不因角色动画自动播放声音。
- 角色的 aria-label 必须包含去向；气泡不作为唯一的屏幕阅读器信息。
- 低高度页面允许滚动；不能为了“看起来一屏”而隐藏写字、答题或家长安全提示。

## 15. 风险、回滚和停止条件

| 风险 | 早期信号 | 对策 |
| --- | --- | --- |
| 动效掉帧 | MuMu 或低端 WebView 滚动/点击明显卡顿 | 只保留 transform/opacity，减少常驻动画，先关闭走动 |
| 角色遮挡内容 | 角色或气泡盖住字、题目或 CTA | 角色舞台独立容器、卡片 z-index 更高、缩小气泡 |
| 路由错误 | 所有角色仍去 growth 或课程 ID 无效 | 用三主题 route matrix 测试，保留 setPage 单一路径 |
| 答题反馈重复 | 一次点击出现两次欢呼或 streak 多加 | 统一 helper，只在真实判定点派发，清理 listener/timer |
| 识字体验误报错 | 第一次“看提示”就出现安慰/错误 | 为 reveal 分支写回归测试，派发点放在真实记账之后 |
| 奖励数据被破坏 | 余额、claimed 或待确认状态异常 | S5 只接现有 commit/action；发现缺少动作时停止并另开需求 |
| CSS 旧内核不兼容 | Android 横屏高度为 0、规则失效 | 保留 vh 回退，禁用 :has()/color-mix()，不引入裸 dvh |
| 用户已有修改被覆盖 | git diff 出现非本任务文件大面积变化 | 只编辑计划范围文件，绝不 reset、checkout 或清理未跟踪文件 |

停止条件：

- 需要新增 storage key、远程资源、动画库或全新的宠物数据模型。
- 需要改变学习判定、奖励确认或战斗玩法。
- 需要重构 S1 已验收的场景条 DOM 才能做 S2。
- 800×360 下主卡、字卡或必要按钮无法同时可用。

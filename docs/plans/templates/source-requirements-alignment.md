# Txxx — 原始需求对齐表

> 这张表只做一件事：确认“原始需求文档里的点”已经被映射进任务需求分解，而不是让后续方案、计划、代码一直围着一个不完整的需求表自洽。

## 什么时候必须先做

- 已经有原始需求文档、聊天纪要、图片标注说明、论文摘录、旧方案说明时
- 需求讨论已经结束，准备冻结 `requirements-checklist.md` 前
- 准备进入 `/plan-checklist`、`/solution-loop`、第一次 `/gate` 前

简单任务可简化，但只要存在明确的上游需求材料，仍建议至少快速列一版。

## 使用方法

1. 先把所有原始需求来源列出来
2. 再把每个来源里的关键需求点拆出来
3. 为每个需求点填上它映射到的 `requirements-checklist.md` 行 ID
4. 若暂不进入本轮，明确写成 `延期` / `不适用`，不要留空
5. 若发现某个原始需求点还没有对应行，先补 `requirements-checklist.md`

## 状态建议

- `已映射`
- `已合并`
- `延期`
- `不适用`
- `待对齐`
- `缺失`

## 收口检查

- [ ] 所有原始需求来源都已列出
- [ ] 所有关键原始需求点都已映射、合并、延期或标记不适用
- [ ] 没有“只在原始需求里出现、但 `requirements-checklist.md` 里没有”的点
- [ ] 若有延期或不适用，原因已写清
- [ ] 已确认可以基于当前需求分解进入方案阶段

# 领域画像索引

> 领域画像负责把“同一套模板骨架”翻译成不同领域更顺手的默认流程。

## 怎么用

1. 先选一个主画像作为默认入口
2. 再按画像里的“验证重点”和“内部件触发条件”装配模板
3. 如果项目混合两种以上画像，保留一个主画像，次画像只补测试和证据要求

## 四类画像速览

| 画像 | 默认入口 | 重点测试 | 常见证据 |
|---|---|---|---|
| [software-dev.md](./software-dev.md) | `task-lite.md` / `task.md` | 单元、集成、回归、兼容 | diff、日志、命令输出、接口行为 |
| [algorithm.md](./algorithm.md) | `task.md` / `task-full.md` | 指标、阈值、样本覆盖、基线对比 | 指标表、样本清单、可视化、对比报告 |
| [ui-optimization.md](./ui-optimization.md) | `task.md` | 截图、用户路径、信息层级、回归 | before/after 截图、流程图、交互说明 |
| [deep-learning.md](./deep-learning.md) | `task-full.md` / `loop-spec.md` | 数据集、标签、复现、训练验证测试 | 数据集说明、配置、曲线、checkpoint、评估表 |

## 选择原则

- 任务主体是代码行为变化，优先软件开发
- 任务主体是指标与规则正确性，优先算法
- 任务主体是可用性、布局、交互清晰度，优先 UI 优化
- 任务主体是训练、微调、实验和模型对比，优先深度学习

# 算法画像

> 适合规则策略、视觉算法、阈值调优、标定评估和算法验证类任务。

## 推荐公开模板

| 场景 | 默认入口 | 何时升级 |
|---|---|---|
| 小范围参数或阈值调整 | `task.md` | 一旦需要多轮验证或样本分层就升级 |
| 多模块算法验证 | `task-full.md` | 需要阶段 Gate 或多人并行时使用 |
| 持续实验闭环 | `loop-spec.md` | 需要 maker/checker/golden 循环时使用 |

核心控制面里，`requirements-checklist.md` 和 `test-plan.md` 通常比纯代码任务更重要，因为算法任务很容易“实现正确但口径不对”。

## 测试与证据重点

- 指标口径：Precision、Recall、FPR、FNR、耗时等是否定义一致
- 样本覆盖：正常、异常、边界、极端样本是否都有
- 基线对比：是否能和当前版本或参考算法直接比较
- 真值校验：指标通过是否真的代表业务成功

常见证据包括指标表、样本清单、混淆矩阵、可视化对比图、阈值扫描结果。

## 常拉起的内部件

| 内部件 | 触发条件 |
|---|---|
| `source-requirements-alignment.md` | 原始需求文档里指标多、容易漏项 |
| `task-decomposition.md` | 需要拆成数据准备、算法修改、评估、复核多个链路 |
| `change-request.md` | 测试证伪原假设，或换了一套评价口径 |

## `/grill-me` 应追问什么

- 成功指标到底是什么
- 真值或标注从哪里来
- 基线版本和比较方式是什么
- 失败样本是否要单独留证据

如果答案里仍然有“差不多”“看着行”，就不要急着进执行。

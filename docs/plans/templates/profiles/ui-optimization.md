# UI 优化画像

> 适合桌面界面整理、信息层级重排、交互减负、视觉一致性和可用性改进类任务。

## 推荐公开模板

| 场景 | 默认入口 | 何时升级 |
|---|---|---|
| 单页微调 | `task.md` | 影响多个页面或涉及流程重构时升级 |
| 多页面交互改造 | `task-full.md` | 需要分阶段截图审查或并行执行时使用 |

UI 任务虽然常常改动代码不多，但验证和证据通常比普通文档任务更重。

## 测试与证据重点

- before / after 截图是否清楚表达变化
- 关键用户路径是否变短、变顺手
- 信息层级是否更清晰，主次动作是否更明确
- 不同分辨率、主题或状态下是否出现回归

常见证据包括页面截图、操作路径说明、可用性问题清单、交互前后对比。

## 常拉起的内部件

| 内部件 | 触发条件 |
|---|---|
| `requirements-source.md` | 需求来自截图批注、客户反馈、设计意见汇总 |
| `task-decomposition.md` | 页面多、改动链路长、需要拆成多个界面子任务 |
| `change-request.md` | 评审后发现方向错了，或用户临时改变视觉目标 |

## `/grill-me` 应追问什么

- 用户最痛的页面或流程是哪一个
- 这次更看重效率、学习成本还是视觉统一
- 必须保留哪些现有控件或操作习惯
- 交付时需要什么截图、标注或演示顺序

如果目标只是“更好看一点”，要继续问到可验证的改进点。

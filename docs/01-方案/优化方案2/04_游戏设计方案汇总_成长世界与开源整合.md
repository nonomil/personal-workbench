# 游戏设计方案汇总（成长世界 · X调研 · 开源游戏整合 · 花园/地图/建造三方向）

> 背景：用户希望"游戏不能只是装饰，宠物不能只是摆设"，要求基于开源资源做真实调研而非凭空设计。以下为四份平行调研/设计输出的完整整理。

---

## 方案A：X（推特）信号 + 开源游戏整合（早期版本）

### 结论先说
**不是整包克隆**参考项目，而是抽它们验证过的**产品机制+信息架构+UI模式**，嵌进豆豆工作台现有壳（学习主线、阳光/券、本地快照）。

这轮已按分析改了「游戏世界」与「伙伴小屋」的界面结构。

### 一、X上能用到的信号（不是抄链接，是抄模式）

| 来源类型 | 代表 | 可迁移点 |
|---------|------|---------|
| 养成爆款 | Finch/自护宠物类 | 吉祥物是打开理由，不是装饰；习惯完成=宠物变好；情绪连接>功能列表 |
| 任务宠物 | PetTask类设想（X上常见build帖） | 完成to-do→宠物心情变化；localStorage；一打开就看懂 |
| 积分/等级泛化 | 中文圈对「成长等级+勋章+连续打卡」的吐槽与认可 | 工作台已有连续/成就——要少而准，别再堆空壳统计 |
| 塔防教育 | HTML5 TD原型、给孩子用的轻TD | 固定路径、少塔种、短局；策略反馈比关卡量重要 |
| 浏览器方块/马里奥 | Canvas教程、Eaglercraft讨论 | 全量MC/马里奥太大；只抽跳/避障或网格建造 |

X上几乎没有「直接fork进学习工作台」的成品，但有清晰共识：**活的伙伴+短局奖励+习惯闭环**，比「完整3A小游戏」更能天天打开。

### 二、提示词里那些链接：拆成「可嵌入的一层」

#### 1. pet-bank（最重要）

**可复用的核心代码逻辑**：
```javascript
// pet-bank风格的宠物数据模型
const petData = {
  name: '小光',
  type: 'light-beast',      // 根据主题映射
  level: 1,                 // 1-4级
  levelName: '蛋',          // 蛋→幼崽→成长→进化
  exp: 0,
  maxExp: 100,              // 每级递增
  hunger: 50,               // 0-100，每小时-2
  happiness: 80,            // 0-100，完成任务+5
  cleanliness: 70,          // 0-100
  lastFeedTime: timestamp,
  lastPlayTime: timestamp
};
```

| 层 | 它怎么做 | 工作台怎么融 |
|----|---------|-------------|
| 积分银行 | 完成目标→余额可见 | 阳光+游戏券双账户：阳光偏养成/商城，券偏开玩 |
| 宠物小屋 | 多维状态+喂食/互动按钮 | 伙伴小屋（饱食/心情/亲密度/经验+喂食/摸摸） |
| 游乐场 | 上图下文卡进iframe小游戏 | 游戏世界三卡（不进iframe，同页Canvas） |
| 沉浸 | 进玩法后收主UI | 游玩台（play stage）固定标题条，主内容在下方 |
| 防刷 | receipt防重复加分 | 已有awardedIds/券按任务批；游戏结算走`grantGameReward` |
| 家长 | 本地优先+可选云 | 继续localStorage+导出；不接重后端 |

**不要搬**：12大场景全图、英语词库射击、家长VPS全套——体量与豆豆主线（识字/数学/拼音）会抢戏。

#### 2. 工作台本体哲学（personal-workbench幼儿版）
- 少文字、大图卡、大方框
- 游戏是学习的延伸，阳光来自真练习
- 已有花园防守DOM版→加的是短局实时奖励层，不是第二套产品

#### 3. 开源游戏链接 → 只抽机制

| 参考 | 抽什么 | 不抽什么 | 落到UI |
|------|--------|---------|---------|
| PVZ类 | 种、阳光、波次、漏怪掉命 | 关卡编辑器、全植物图鉴 | 卡面「塔防·学策略」+种子条+Canvas |
| 马里奥类 | 跳、重力、障碍节奏 | 32关、编辑器 | 卡面「跑酷·练反应」+一键开战 |
| 网页MC | 放块、材料选择、保存 | 3D、生存、多人 | 卡面「创造·不耗券」+网格建造 |

### 三、如何融入工作台（信息架构）
```
主线（每天）          奖励环（3–5分钟）         长期
学习任务 ──阳光/券──► 游戏世界三选一 ──经验──► 伙伴进化
    │                      │                      │
    └── 日历/成就 ◄────────┴── 击退/米数/作品 ────┘
```

### 三条硬规则（产品级）
1. **没券不能开战**（建造例外）—— 练习才是入口
2. **伙伴会变差**（饿/闷）—— 对齐Finch/pet-bank，避免「摆设宠物」
3. **一局≤5分钟**—— 难度只随打卡天数档位微调，不做成第二主业

### 四、UI设计原则

**游戏世界（植物大战页顶部）**
1. 标题区：说明「奖励局/抽机制不搬整游戏」
2. 银行条4格：券·难度档·保卫战绩·闯关最远（数字tabular-nums）
3. 三张玩法卡（上图下文）：上（主题色媒体区+角色图）；下（名称/类型标签/一句机制来源/耗券与纪录）
4. 游玩台：当前玩什么+闭环规则一句话，下面才是Canvas

**伙伴小屋（花园基地）**
- 大头像可点（摸摸）+阶段角标（蛋/幼崽/成长/进化）
- 四条状态条（饱食/心情/亲密/经验）
- 主按钮喂食，次按钮摸摸/去游戏世界
- 文案写清：任务→心情，喂食→饱食，游戏→经验

**视觉原则（贴工作台绿植主题+少slop）**
- 保留豆豆绿主色，不用紫霓虹
- 大触控卡，手机竖排不横溢
- 少emoji装饰，用图与字重做层级

### 五、刻意不做的（避免假"融入"）
- 不嵌Eaglercraft/FullScreenMario整包
- 不把首页改成纯游戏大厅（学习仍是第一路径）
- 不复制pet-bank的12场景大地图（豆豆用"花园+方块"两主题足够）

如果想进一步做到"像pet-bank游乐场"，优先可做两件UI深化：①首页加一条伙伴状态胶囊（饿了跳进小屋）；②进局后全屏游玩蒙层（只留返回+券/波次HUD）。

#### 1.5 宠物养成核心设计模式总结
```
┌─────────────────────────────────────────────────────────────┐
│                    宠物养成 · 核心循环                       │
├─────────────────────────────────────────────────────────────┤
│   📝完成任务 → 💰获得积分 → 🛒购买饲料/道具                │
│        ↑                        ↓                          │
│   🏆宠物进化 ← 📈经验增长 ← 🍖喂养/照顾宠物                │
│   四维状态：饱食度·心情·清洁度·亲密度                       │
│   成长阶段：蛋🥚→幼崽🐣→成长🐾→进化🦸                      │
└─────────────────────────────────────────────────────────────┘
```
关键设计原则（从多个项目中提炼）：
1. **状态衰减机制**：宠物状态随时间缓慢下降，需要持续照顾
2. **正向激励为主**：完成任务获得积分，不因错误扣分
3. **阶段性成长**：多阶段进化提供长期目标
4. **情感连接**：点击互动、个性化命名、专属形象

#### 3.2 游戏化学习平台的设计趋势

从搜索到的多个儿童学习平台项目中，可以总结出以下趋势：
1. **经验值+等级系统**：BrainBuddy使用XP system、levels、achievements
2. **每日任务+连击**：phonics-ai使用daily quests and streaks
3. **自适应难度**：Lumi强调adaptive difficulty that grows with the child
4. **温和设计**：Lumi提出「Celebrate completion, not speed or scores」
5. **本地优先**：部分项目强调local-first

**重要提醒**：Lumi项目特别指出「Most children's educational apps use dark patterns—points, streaks, leaderboards, notifications—to maximize screen time. Lumi is the opposite」。幼小衔接工作台应遵循**正向激励、温和反馈**的原则。

## 方案C：成长世界游戏方案设计（第三轮 · "学习即成长"理念）

> 基于对`pet-bank`、`personal-workbench`、`mario-minecraft-game`以及相关开源项目的调研，结合"成长可视化"讨论，产出的完整游戏方案设计。
> 核心理念：游戏世界的每一寸变化，都是孩子学习成果的真实映照。
> 技术路线：纯DOM/CSS/Canvas实现，不引入游戏引擎，轻量级嵌入工作台。

### 一、设计理念

| 之前的思路 | 现在的设计 |
|-----------|-----------|
| 游戏是独立的"额外模块" | 游戏是学习进度的"可视化呈现" |
| 学完→玩游戏（割裂） | 学的过程=游戏世界在成长（一体） |
| 游戏内容是固定的 | 游戏内容由孩子的学习进度生成 |
| 游戏是"奖励" | 游戏是"成果展示" |
| 孩子为"玩游戏"而学习 | 孩子为"看到世界变化"而学习 |

### 1.2 设计来源
参考`pet-bank`的核心理念——"把完成目标包装成账户余额增长，把坚持习惯包装成宠物养成"。同时借鉴`personal-workbench`幼儿版"少文字、大图卡、大方框"的视觉原则。

> "不是教育孩子，而是和孩子一起玩一个关于成长的游戏。"——pet-bank项目说明

| 学会50个字 | 出现小木屋 | 木屋搭建动画 |

// 学习完成 → 更新游戏世界
function onLearningComplete(module, data) {
  const growthData = loadGrowthData();
  switch(module) {
    case 'literacy':  // 识字
      growthData.garden.flowers.push({
        char: data.char, pinyin: data.pinyin, plantedAt: Date.now(), color: randomColor()

      break;
    case 'math':  // 数学

      break;
    case 'english':  // 英语
      growthData.builder.blocks.push({
        word: data.word, meaning: data.meaning, learnedAt: Date.now(), color: randomColor()
      });
      break;
  }
  saveGrowthData(growthData);
  updateWorldUI(growthData);
}

## 方案D：花园/地图/建造三方向的具体开源项目（第四轮 · 直接可改现成项目）

> 用户思路：与其凭空设计，不如直接找现成的开源项目来改。按"花园""地图""建造"三个方向，筛选可以直接拿来改的项目。

### 🌱 花园方向：SkillBloom

**项目地址**：`https://github.com/Arshgill01/Skill-bloom`

**核心机制**：把学习进度变成一个"会生长的数字花园"，每完成一个任务，树就长出新的枝叶。

| 维度 | 说明 |
|------|------|
| 技术栈 | Next.js 15+Tailwind CSS+Framer Motion+TypeScript |
| 核心算法 | 确定性"有机"随机，用`(i * 123.45) % 1`替代`Math.random()`，确保每次渲染一致 |
| 数据存储 | 浏览器本地保存，关闭页面再打开进度不丢 |
| 动画 | Framer Motion驱动SVG路径动画，树枝是"长出来"的，不是直接出现的 |

**怎么改**：
- 把AI生成课程的部分（Gemini API）换成工作台自己的学习任务数据
- 保留SVG花园渲染引擎，把"一棵树"改成"一个花园"，每个字对应一朵花
- 去掉Next.js依赖，把核心渲染逻辑抽成纯React组件或vanilla JS

### 🗺️ 地图方向：LearningMap

**项目地址**：`https://github.com/openpatch/learningmap`

**核心机制**：交互式学习路径地图，学生可以追踪进度、按自己的节奏学习。

| 维度 | 说明 |
|------|------|
| 多平台 | Web App、VS Code插件、React组件、Web Component |
| 核心概念 | 教师创建地图→学生访问地图→追踪进度 |
| React组件 | 可直接`npm install`嵌入任何React应用 |

**怎么改**：
- 直接用React组件嵌入工作台
- 把"学习路径节点"映射为"打卡天数"（30天对应30个节点）
- 节点颜色：灰色（未到）→蓝色（今天）→绿色（已完成）

### 🗺️ 地图备选：MapFlow

**项目地址**：`https://github.com/rongyan-123/MapFlow`

**核心机制**：技能树可视化，节点按依赖关系排列，颜色实时反映学习状态。

**特点**：
- 自动布局（dagre算法），节点再多也不重叠

# 文档一：字卡游戏系统设计方案


## 一、设计目标

**不是做成“闪卡工具”，而是做成“有学习深度的卡片互动系统”。**

| 维度     | 闪卡工具 | 字卡游戏系统            |
| -------- | -------- | ----------------------- |
| 交互     | 看→翻→记 | 看→听→选→配对→组词→闯关 |
| 学习深度 | 机械记忆 | 理解性记忆              |
| 反馈     | 无/简单  | 即时+视觉+音效          |
| 闭环     | 无       | 认→练→测→复             |

## 二、核心机制：5步学习闭环

参考洪恩识字的“玩、认、练、写、说”和 kids-learning-cards 的卡片设计体系：

```
┌─────────────────────────────────────────────────────────────┐
│                    字卡学习闭环                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① 认（感知）   ② 练（巩固）   ③ 测（检测）   ④ 组（运用）   ⑤ 复（复习）  │
│      ↓              ↓              ↓              ↓              ↓         │
│  看字+听音     配对游戏      听音选字      组词配对      SM-2算法       │
│  看配图+跟读   字图配对      看图选字      拖拽组词      自动排期       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 四、卡片类型体系（直接复用 kids-learning-cards）

kids-learning-cards 定义了5种卡片类型，每种有独立的主色和内容结构：

| 卡片类型   | 主色 | 内容结构                          | 触发示例          |
| ---------- | ---- | --------------------------------- | ----------------- |
| **识字卡** | 红色 | 字源故事 / 字形演变 / 偏旁家族    | 「字卡：山」      |
| **词语卡** | 绿色 | 词义概括 / 同类词族 / 词由字组成  | 「词卡：苹果」    |

## 五、游戏模式设计

### 模式1：Flip学习模式（参考 Flashcards Game）

**机制**：展示卡片正面（字/图）→ 点击翻转 → 显示背面（拼音/组词/释义）

**交互**：
- 点击卡片翻转（CSS 3D翻转动画）
- 点击🔊听发音（Web Speech API）
- 左右箭头翻页
- “已掌握”按钮标记进度

### 模式2：Quiz测验模式（参考 Flashcards Game）

**机制**：显示问题 → 输入/选择答案 → 即时判断对错

**题型**：
- 听音选字（4选1）
- 看图选字（4选1）
- 看字选拼音（4选1）
- 看字选组词（4选1）

### 模式3：配对游戏（参考 Letter Hunt / kanji-pair-game）

**机制**：在汉字网格中找出配对

**变体**：
- **字图配对**：4×4网格，字配图
- **组词配对**：16格汉字，两两配对组成词语
- **拼音配对**：声母配韵母

### 模式4：Letter Hunt 找字游戏（参考 reading-for-kindergarten）

**机制**：在一堆字母/汉字中找出目标字

**交互**：显示目标字 → 在干扰项中点击正确字 → 正确则进入下一题

# 文档二：组词游戏系统设计方案


## 一、设计目标

**从“认字”到“用字”，让孩子在游戏中理解字在词中的用法。**

核心逻辑参考魏智渊方法论：“词是一种概括——词不是机械地贴在某个具体事物上的标签，而是对大量经验、现象、关系的概括。”

## 二、核心机制

### 机制1：组词开花（核心玩法）

```
         ┌───────┐
         │  山   │  ← 核心字
         └───────┘
        /    |    \
   ┌────┐ ┌────┐ ┌────┐
   │大山│ │山水│ │火山│  ← 点击选择正确组词
   └────┘ └────┘ └────┘
   ┌────┐ ┌────┐ ┌────┐
   │山村│ │山泉│ │上山│
   └────┘ └────┘ └────┘
```

**交互**：显示核心字 → 从6-8个选项中选出3个正确组词 → 全部选对过关

### 机制2：配对消除（参考 H5组词小游戏）

**机制**：从汉字网格中两两配对组成词语，配对成功消除

**技术参考**：
- 使用 CSV 格式词库，通过 Ajax 异步加载
- 匹配成功触发 SVG 爆炸消除动画
- 10秒无操作自动提示

### 机制3：汉字配对（参考 kanji-pair-game）

**机制**：16格汉字网格，点击两个汉字配对组成词语

**规则**：
- 配对正确 → 两格变绿，词语加入列表
- 配对错误 → 两格变红后恢复
- 全部配对完成 → 新网格

## 五、游戏模式设计

### 模式1：组词开花（单人）

- 显示核心字
- 从6-8个选项中选出正确组词（3个）
- 全部选对 → 星星+1 → 下一字
- 选错 → 温和提示，不扣分

### 模式2：配对消除（双人/单人）

- 4×4或6×6汉字网格
- 点击两个汉字配对组成词语
- 配对正确 → 消除 + 得分
- 配对错误 → 恢复 + 提示

### 模式3：组词挑战（计时）

- 60秒内尽可能多地组词
- 每正确组词一个 +10分
- 显示最终得分和组词列表

## 六、技术实现

### 6.1 组词配对核心逻辑（参考 kanji-pair-game）

```javascript
// 基于 kanji-pair-game 的配对逻辑
class WordPairGame {
  constructor(words) {
    // 从词库中选8个词，提取16个汉字
    this.grid = this.buildGrid(words);
    this.selected = [];
    this.matched = [];
  }
  
  buildGrid(words) {
    // 每个词拆成两个字，打乱排列
    const chars = words.flatMap(w => w.split(''));
    return shuffle(chars);
  }
  
  select(index) {
    if (this.selected.length === 2) return;
    this.selected.push(index);
    // 检查是否配对成功
    if (this.selected.length === 2) {
      const word = this.getWord(this.selected);
      if (this.isValidWord(word)) {
        this.matched.push(word);
        this.selected = [];
        return true;
      } else {
        // 配对失败，恢复
        setTimeout(() => this.selected = [], 500);
        return false;
      }
    }
  }
}
```

# 文档五：学习体验与交互设计参考


## 一、洪恩识字的设计启示

洪恩识字的成功在于完整的“玩、认、练、写、说”闭环：

| 环节 | 洪恩做法                           | 工作台可借鉴               |
| ---- | ---------------------------------- | -------------------------- |
| 玩   | 互动小情境，把汉字变成可操作的对象 | 字卡游戏化，每个字都有互动 |
| 认   | 动画讲解+配图+发音                 | 字源故事+配图+发音         |
| 练   | 配对/选择等互动练习                | 组词配对/听音选字          |
| 写   | 描红/书写练习                      | 笔顺动画（已有165字数据）  |
| 说   | AI学伴互动                         | 跟读录音（Web Speech API） |

## 二、儿童友好的交互原则

参考 chineseproject 的设计：大按钮、清晰界面、直观操作、触控优化

| 原则         | 实现                      |
| ------------ | ------------------------- |
| **大按钮**   | 所有可点击区域 ≥ 52px     |
| **即时反馈** | 每个操作都有视觉+音效反馈 |
| **无惩罚**   | 错误只提示，不扣分不羞辱  |
| **进度可见** | 随时看到完成了多少        |
| **鼓励为主** | 完成即有正向反馈          |

## 三、游戏化激励体系

参考 chineseproject 的激励设计：

| 激励类型       | 实现方式                     |
| -------------- | ---------------------------- |
| **积分系统**   | 完成任务获得星星/阳光        |
| **徽章收集**   | 里程碑成就（如“组词小达人”） |
| **等级解锁**   | 循序渐进的学习路径           |
| **进度可视化** | 直观展示学习进度             |

## 四、音效与反馈设计

| 事件     | 反馈类型       | 实现方式                    |
| -------- | -------------- | --------------------------- |
| 卡片翻转 | 视觉+音效      | CSS 3D翻转 + Web Audio      |
| 答对     | 视觉+音效+文字 | ✅ + 上升音调 + “太棒了！”   |
| 答错     | 视觉+音效+文字 | ❌ + 柔和提示音 + “再想想～” |
| 过关     | 全屏庆祝       | 🎉 撒花动画 + 庆祝音效       |
| 获得星星 | 飘字动画       | ⭐ +10 向上渐隐              |

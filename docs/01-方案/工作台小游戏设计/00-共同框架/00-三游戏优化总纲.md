- 日期：2026-08-15
- 状态：方案（未改代码）

- 输入：本目录 4 份 DS 历史设计、三游戏落地改造方案、`prj/games/` 现行代码、外部参考（游戏化学习工作台笔记、"什么是真正的工作台"）。

## 1. 定位

三个小游戏不是"学完的奖励"，而是**成长引擎的三个入口**：真实游玩行为写入与学习同一份账本，反过来学习进度改变游戏难度与奖励。检验一切设计的滤网（来自"什么是真正的工作台"）：

> 任何货币、连击、仪表，必须由真实的学习或游玩痕迹支撑，否则砍掉。

三世界能力叙事（给孩子与家长讲的话术，写进 UI 文案与周报）：

| 世界 | 能力 | 一句话 |
| --- | --- | --- |
| 花园保卫战 | 规划力 | 想好再种，阳光要省着花 |
| 方块世界 | 创造力 | 一块一块搭出自己的家园 |
| 横版闯关 | 执行力 | 手眼配合，坚持到旗子 |

## 3. 共同账本与成长框架（代码已落地，分册在其上加建）

`prj/games/shared/workbench-bridge.js`（存储键 `petbank_huchuliang_preschool_workbench_state_v1`）已提供：

- **钱包**：`growth.sunlight`（通用阳光）、宠物星芒 xp/level、花园行动能量。
- **发奖**：`awardSunlight`（eventKey 去重、单次上限 40、**每日游戏阳光合计上限 80**）。
- **进度**：`growth.worldGames.<gameId>`（花园 `unlockedStage/clearedStages/stars`，方块 `rank/questsDone/...`，横版 `unlockedLevel/clearedLevels/stars/coinsTotal/bestTime`）。
- **长线**：冒险点 → 冒险等级 7 级（`萌芽旅人`→`传说冒险家`），等级反哺各游戏（花园开局阳光 0→60、横版金币加成、方块晶体加成）。
- **里程碑徽章 11 枚**：单游戏进度、7/30 天游玩、三界同日、20 星收藏。
- **节奏**：每日每世界打卡戳 +3 阳光、三界同日 +8、周目标（4 天/周 +15、三界日 +12）。
- **学习联动**：`getPlayMods()` 按识字量分档（<100 简单 / 100–200 普通 / >200 困难，`enemySpeed`/`sunMult`/`extraMob`）。
- **家长侧**：`getWeeklyReport()` 周报（天数、各世界进度、徽章、建议）。

**共同缺口（P0，三分册都要接）**：

1. `getPlayMods()` 目前只有方块世界调用；花园、横版未接学习难度联动。
2. 徽章与冒险称号缺"消费面"——游戏内不展示、解锁瞬间没有仪式感（只有阳光数字变化）。
3. 星芒（unicorn）在三游戏内零出场，账本涨 xp 但孩子看不见"伙伴在陪我玩"。

## 4. 陪伴设计共同规范

参考外部笔记"专属伙伴 + 成长地图 + 学习证据"的做法，三游戏统一：

- **伙伴出场**：星芒以小头像常驻游戏 HUD 角落；开局一句欢迎、通关一句夸奖、失败一句打气（文案池 8–12 条/游戏，按 `petLevel` 解锁更亲昵的称呼）。
- **仪式感**：里程碑徽章解锁时游戏内弹全屏庆祝卡（徽章图 + 称号 + 星芒庆祝姿势），而不是只在工作台成长页事后看到。
- **成长可见**：每游戏结算页固定三行——本局所得（阳光/星）、长线进度（冒险等级进度条）、下一个目标（离下个里程碑差多少）。
- **证据感**：周报里每个世界至少一条具体事实（"方块世界搭了 40 个方块"），不是空的打勾。

## 5. 美术统一规范

- **两套主风格**：花园保卫战 = 儿童绘本卡通（v4 僵尸批次已按此风格）；方块世界 + 横版闯关 = Paper-MC 像素家族（横版 §8 已统一，共用 `pixel-tiles.js` 代码地砖）。不再追求三游戏一套风格。
- **生图三铁律**（沿用 `DS--游戏设计--生图.md`）：① JPEG 必须抠底（品红幕布 + 脚本 key）；② 生成前写清用途规格（尺寸、对齐、平铺）；③ 规则图形（地砖、格子）代码画，不生图。
- **版权**：PopCap / Nintendo / Mojang 素材与商标措辞一律不进仓；生图提示词去商标化。
- **资产归宿**：发布位 `prj/assets/generated/<theme>/published/` 与 `prj/games/<game>/assets/`，每游戏维护 `assets/manifest.md` 记录用途与关卡映射。

**音效规范（2026-08-15 裁决，此前悬空）**：

1. 一期允许**关键反馈短音**：里程碑庆祝卡、升段仪式、检查点存档、通关/新纪录。范围之外（BGM、脚步、环境音）一律不做。
2. 全部用 **Web Audio 代码合成**（platform-quest 已有 AudioContext 先例，抽公用小工具复用），**不引入音频文件**——不占素材仓、无版权敞口、无加载失败路径。
3. 默认音量低（≤0.3 增益）；尊重系统静音；全局音效开关挂工作台设置页（三期），一期各游戏内不单独做开关。

## 6. 实施顺序与依赖

按"先接通、再加深、后扩量"分三期，花园 → 方块 → 横版逐个收尾（与历史落地顺序一致）：

| 期 | 内容 | 分册对应 |
| --- | --- | --- |
| 一期（接通） | 三游戏接 `getPlayMods`；结算页三行规范；星芒 HUD 出场 + 文案池；里程碑庆祝卡 | 各册 01、03 |
| 二期（加深） | 花园 7–12 关新敌人节奏与新植物；方块工具等级挖矿门禁 + 家园展示；横版手感三件套验证与关卡减肥复查 | 各册 01、02 |
| 三期（扩量） | 方块区域化（第二 biome）；花园/横版新关卡批次；徽章相册与赛季性周挑战 | 各册 04 远期节 |

**每期铁规**：改 storage/奖励结构前先查 `docs/00-总控/变更与同步规则.md`；`tests/world-games.test.mjs` 合同同步更新；不改 localStorage key。

## 7. 验收总标准

- 一份账本：全程只出现 `petbank_huchuliang_preschool_workbench_state_v1`，无新增顶层 key、无第二货币。
- 三游戏均调用 `getPlayMods` 且难度差异可被测试断言。
- 结算页三行、星芒出场、徽章庆祝卡在三游戏行为一致（合同测试覆盖）。
- 单局时长守住：花园 ≤3 分钟、方块单任务 ≤5 分钟、横版 ≤2 分钟。
- 每日阳光上限 80 不被绕过；失败不扣已有阳光。

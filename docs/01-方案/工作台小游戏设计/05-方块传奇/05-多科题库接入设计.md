# 方块传奇 · 多科题库接入设计

> 状态：2026-08-19 **设计已改锁（按数量配比）**。配菜已进第 1 关世界。手玩步骤见 [06-多科配菜测试方案](06-多科配菜测试方案.md)。

> 本文只定合同。实施另开计划，先写失败测试。

## 1. 锁定结论

工作台各科已经是题库。游戏缺的是薄适配，不是新库。

**双车道 + 按熟悉英语词数量配比配菜。从第 1 关就开始，不锁后期关。**

| 车道 | 吃什么 | 写回 | 决定什么 |
| --- | --- | --- | --- |
| 主车道 | 现有 597 英语词 | `minecraft.mastery` | 近战、Boss 蓝罩、主题材料、图鉴、每日一词 |
| 配菜 | 识字 / 拼音 / 拼读 / 口算 | 各科自己的槽 | 石碑、商人折扣、练一句；**不决定暴击** |

关卡只决定气候皮和出题带（L1 字 / 20 以内口算），**不决定「能不能学到这科」**。只玩第 1 关，熟悉够多英语词，四科配菜都会出现。

不做：按关整关换科、战斗题每 N 道切科目、把汉字/算式塞进 `words.js`、新 localStorage key。

## 2. 为什么改成按数量

上一版按关绑科目：第 6 关才口算、第 3 关才拼音。孩子若一直停在草原，后面的科等于没学。这个缺口是真的。

改成「熟悉了多少个**不一样的**英语词 → 欠多少配菜」。同一词反复答对不加算。工作台已经会的字/题会抵扣，避免两边各刷一遍。

仍不把配菜塞进近战：计数只用来**点亮石碑和商人**，不打断正在打的史莱姆。

## 3. 配比（锁死）

`F` = 生涯熟悉英语词个数（`minecraft.mastery` 里 `ready` / `maintenance` 的不同词，和任务「不一样的词」同口径）。

`known(科)` = 该科工作台掌握度里已经 `ready` / `maintenance` 的条数。

```text
欠识字 = max(0, floor(F / 4) * 2 - known(literacy))
欠拼音 = max(0, floor(F / 8)     - known(pinyin))
欠拼读 = max(0, floor(F / 12)    - known(phonics))
欠口算 = max(0, floor(F / 16)    - known(math))
```

用数量说话：

| 熟悉英语词 F | 新欠的配菜（若工作台还没会） |
| --- | --- |
| 0–3 | 无。前几分钟只打英语 |
| 4 | 识字 2 道 |
| 8 | 识字再 +2，拼音 1 道 |
| 12 | 识字再 +2，拼读 1 道 |
| 16 | 识字再 +2，口算 1 道 |
| 20 | 识字再 +2。之后每 +4 词再欠 2 识字，每 +8 / +12 / +16 各欠 1 道另外三科 |

一次坐下最多做 **6** 道配菜，多出来的欠账留到下一局石碑/商人。一局不会变成语文课。

出题优先抽该科 **due（今天该复习）**，没有 due 再抽未见项。识字带按已会字数：`<80` 用 L1，之后 L2…，不一次铺 1500 字。口算：`F<20` 数数/比较，之后 20 以内现算。

`Port.sideDue({ enFamiliar, tracks })` 只算欠账。`Port.nextDue(due, opts)` 取下一题。关卡号不再决定科目。

## 5. QuestionPort 合同

新文件：`prj/games/blocklegend/data/question-port.js`（纯函数）。`game.js` 只装配。

```text
Question = {
  id, kind, prompt, stem, speak, lang, mode, choices, answer,
  masteryTrack, masteryKey, band
}

Port.sideDue({ enFamiliar, tracks }) -> { literacy, pinyin, phonics, math }
Port.nextDue(due, opts) -> Question | null
Port.grade(question, input) -> { ok, kind }
```

`opts`：`avoidKeys[]`、`dueKeys[]`、`salt`、`band`。口算 L3+ 调 `buildPracticePool`。

判题：识字/拼音/口算不用 `matchHeard`。拼读可复用（仍是英文）。错两次换下一题。

写回：`WorkbenchGameBridge.recordSubjectAnswer(track, key, correct)`。识字走 `saveLiteracy`，其余走 `saveSubject`。禁止 `recordWordAnswer`。不新开存储 key。

## 6. 世界里怎么出现（任何关都一样）

欠账 > 0 才改绑表面。没欠账就是原来的英语金块/普通商店。

1. **石碑**：远处金块最多 6 块。按欠账顺序绑：识字 → 拼音 → 拼读。看向时显示科目名，不是英语词牌。
2. **商人**：任意关，打开商店前若欠口算，先做 1 道；对了本单九折，错了原价仍能买。
3. **练一句**：欠拼读时默认出 CVC，否则仍是英语场景句。不新建识别器。
4. **近战 / Boss 蓝罩**：永远英语。`bossMechanic` 不改。

奖励：石碑 +3 金币，不算熟悉英语词，不发主题材料。商人只改价。阳光规则不变。

HUD：`还欠 识字2 拼音1`。家长页不新开。

## 7. 加载与失败

按**当前欠账的科**懒加载，不按关、不打进首屏。

```text
literacy / pinyin / phonics / math → 对应引擎 + JSON
```

加载失败：该科欠账本局跳过，主车道照常。Toast 一句「识字板暂时没有」。

TTS：打开配菜才切 `zh-CN`，关掉立刻 `en-US`。

## 8. 明确不做

- 不按关锁死「这关才能学某科」。
- 不按答对次数刷配菜（同一词刷 10 次不会变出 5 道识字）。
- 不把配菜塞进近战轮询。
- 不把识字/拼音/口算写入 `words.js` / 图鉴阶段 / `familiarIds`。
- 不新 localStorage key，不改 `engine.js`，不开 T8.4。
- 第一刀不做家长钉科目、诗歌、运动。

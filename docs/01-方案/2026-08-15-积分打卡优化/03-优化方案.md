# 03 · 优化方案（P0 / P1 / P2）

> 原则：不推倒重来，只做口径统一、账本补漏、可见性增强。所有项都必须满足 `00-README.md` 的五条红线。
> 每项标注：改动面（文件）、验收标准、与既有计划包是否撞域。

## P0：口径与账本（必须做，先做）

### P0-1 打卡双层口径统一 + "点亮"文案化

**问题**：`checkinDates`（首次行动）与地图徽章（全日完成）是两个统计，但文档和 UI 都混称"打卡"；哲学文档反对人为打卡叙事。

**做法**：

1. 命名分层：代码内部字段不动；展示层统一——`checkinDates` 对应的 UI 文案从"打卡"改为"点亮"（今日已点亮 / 本月点亮 N 天 / 连续点亮 N 天）；"全日任务完成"在 UI 中称"完美日"（地图徽章描述同步）。
2. 在 `docs/data-model.md` 增补一节"点亮日 vs 完美日"口径定义，写明两个统计的来源函数与用途。
3. 不新增任何手动打卡按钮；不改变 `recordAction` 写入逻辑。

- 改动面：`prj/app.js`（文案）、`prj/preschool-achievements.js`（徽章描述文案）、`docs/data-model.md`。
- 验收：全仓 UI 用户可见文案无"打卡"歧义残留（日历、首页、花园、徽章描述）；`npm test` 全绿；现有测试中断言中文文案的用例同步更新。
- 撞域：`T20260815-B1-docs-truth` 也在做文档回真——**先做本项的代码文案，再让 B1 统一收口文档**，或合并进 B1 执行，二选一（见 04）。

### P0-2 旁路记账补漏

**问题**：向日葵技能与防守棋盘向日葵 tick 只加 `sunlight`，不加 `totalSunlightEarned`（`prj/preschool-garden.js:379-386,565-567`），导致"累计获得"统计与徽章/成长驱动的口径漂移。

**做法**：裁决两个方向之一（执行时先侦查再定）：

- 方向 A（推荐）：向日葵产出视为"游戏内资源循环"，**保持不进总账**，但在 `docs/data-model.md` 写明"totalSunlightEarned 只统计学习+游戏桥入账"，并给防守 UI 加一行小字说明。
- 方向 B：补记入 `totalSunlightEarned`（不进 `unicorn.xp`，避免游戏刷级）。

无论哪个方向，**必须加合同测试**锁定裁决结果。

- 改动面：`prj/preschool-garden.js`（方向 B 时）或仅 `docs/data-model.md` + 测试（方向 A）。
- 验收：新增测试断言向日葵产出的记账行为；`npm test` 全绿。
- 撞域：无。

### P0-3 `claimReward` 合同测试补齐

**问题**：兑换扣余额、重复兑换拒绝无独立单测（B3 S1 改造家长确认前，先把现状锁住）。

**做法**：新增 `tests/preschool-rewards-claim.test.mjs`，覆盖：余额不足拒绝、扣款正确、`claimedRewardIds` 幂等、兑换不影响 `totalSunlightEarned`。

- 改动面：仅测试文件。
- 验收：先对现状全绿；B3 S1 改造时这组测试改写为 pending 流程的基线。
- 撞域：B3 S1 会重构此处——本项是它的**前置保险**，不冲突。

## P1：可见性与"还差一点"（第二批）

### P1-1 日历升级为行动热力图

**问题**：日历只显示"本月点亮天数、当前连续"；哲学文档主张 GitHub 热力图式自动沉淀呈现。

**做法**：`#calendar` 页把本月网格升级为强度分档热力格——每天按"当日入账事件数"分 0/1/2/3+ 四档着色（数据从 `awardedIds` 中按日期前缀聚合，`plan:{id}:{date}`、`daily-checkin:{date}` 均可解析日期；无法解析日期的事件不计强度，只要 `checkinDates` 含当日就至少 1 档）。完美日加一个星标角标。

- 改动面：`prj/app.js`（日历渲染）、可能新增纯函数到 `prj/child-growth.js`（`dailyIntensity(growth, month)`）。
- 验收：纯函数单测（跨月、补签日显示为点亮但无强度加成）；视觉真机检查。
- 撞域：无。

### P1-2 "还差 X"进度提示（借鉴 Kids-Reward，MIT）

**做法**：三处加"还差"文案，全部读现有数据，零新字段：

1. 奖励商城每张卡：`还差 N 阳光`（已有进度条，补文字）。
2. 徽章收集箱灰色占位：`再认 12 个字就点亮`（19 枚成就已有条件函数，补一个 `progressText`）。
3. 连续奖励卡：`再点亮 2 天领取`。

- 改动面：`prj/app.js`、`prj/preschool-achievements.js`。
- 验收：每类至少一条 UI 合同测试；`npm test` 全绿。
- 撞域：B3 S3 也做"连击徽记文案"——若 B3 先执行，本项 3 号提示并入 B3 S3；否则本项先做，B3 复用。

### P1-3 徽章展示层统一

**问题**：19 枚成就徽章（收集箱）与 11 个世界游戏里程碑（`worldGames.meta.badges`）是两套展示，孩子和家长看不到全貌。

**做法**：收集箱增加"世界勋章"分组，只读 `worldGames.meta.badges` 渲染，**不合并判定逻辑、不迁移存储**。家长报告页徽章墙同步。

- 改动面：`prj/app.js`（收集箱渲染）、`prj/preschool-achievements.js`（若分组渲染函数在此）。
- 验收：收集箱显示 19+11 两组；解锁判定测试零改动仍绿。
- 撞域：无（不碰 `workbench-bridge.js`）。

### P1-4 学习专区展示阳光余额

**问题**：`#courses` 页无阳光余额，孩子完成课程只有 toast，看不到账本变化。

**做法**：学习专区头部复用首页 `pixel-hud-sun` 组件显示余额。

- 改动面：`prj/app.js`。
- 验收：UI 合同测试 + 真机；不改任何发放逻辑。
- 撞域：B2 在改学习专区入口——若 B2 未完成，本项延后到 B2 验收后做，避免同文件冲突。

5. 恢复券、新增第二货币、排行榜。
6. 改动 `workbench-bridge.js` 的 80/40 上限与去重逻辑。

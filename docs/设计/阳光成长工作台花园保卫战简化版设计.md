# 阳光成长工作台：花园保卫战简化版设计

> 状态：已实施的 MVP 设计基线；当前验收以 `docs/输出/2026-08-03-花园保卫战MVP验收报告.md` 为准。后续扩展仍需单独评审。

## 1. 产品定位

这是幼儿学习工作台里的 1-3 分钟原创反馈小游戏。它把完成学习活动转化为阳光和守护进度，不替代课程，不惩罚孩子，也不要求复刻完整商业塔防。

## 2. 最小可玩闭环

1. 孩子进入“花园保卫战”。
2. 顶部显示今日阳光、已解锁植物和当前波次。
3. 点击一张已解锁植物卡，再点击 5 路 × 6 列中的一个空格。
4. 放置消耗阳光；阳光不足时给明确提示，不改变学习进度。
5. 僵尸按波次从右侧进入某一路，最多同时 3 只。
6. 攻击植物按固定冷却自动发射；坚果墙只阻挡，向日葵产阳光。
7. 当前 MVP 形成持续游玩的短局；清完当前波次显示“花园安全”和收集反馈，不扣阳光、不扣学习奖励。

## 3. 当前 MVP 规则基线

以下参数以当前代码和验收报告为准，后续文档不能把候选扩展误写成已实现能力。

| 对象 | 作用 | 第一版边界 |
| --- | --- | --- |
| 向日葵 | 每 5 个游戏 tick 生成 10 阳光 | 不参与攻击 |
| 豌豆射手 | 同一路单体攻击 | 每 1 个 720ms 游戏 tick 发射，命中扣 1 生命 |
| 坚果墙 | 吸收僵尸啃咬 | 不发射豌豆，生命 8 |
| 普通僵尸 | 基础推进 | 生命 3，每 3 tick 移动一次 |
| 路障僵尸 | 高生命推进 | 生命 5，每 3 tick 移动一次 |
| 铁桶僵尸 | 更高生命推进 | 生命 7，每 4 tick 移动一次 |

当前入口按成长进度解锁植物；战斗规则集中在 `preschool-garden.js`，不由 DOM 文本决定。当前验收覆盖向日葵、豌豆射手、坚果墙和三类僵尸；寒冰射手、樱桃炸弹虽然已有规则目录，但不属于本轮页面验收闭环。

## 4. 后续候选规则

寒冰射手的减速和樱桃炸弹的 3×3 清除已保留为规则层候选能力，但尚未作为本轮最小闭环的发布承诺。若后续开放，需要补充页面入口、独立测试、移动端验收和奖励边界评审。

## 5. 推荐状态模型

保留 `growth.garden` 作为存档边界，在其下增加版本化 `defense`：

```js
{
  version: 1,
  selectedPlantId: 'plant-peashooter',
  plants: [{ id: 'plant-1', plantId: 'plant-peashooter', lane: 2, column: 1, health: 3, maxHealth: 3 }],
  zombies: [{ id: 'zombie-1', kind: 'zombie-basic', lane: 2, column: 5, health: 3, maxHealth: 3, slowTicks: 0 }],
  projectiles: [],
  wave: 1,
  tick: 0,
  status: 'ready'
}
```

`growth.garden.defense` 是现有本地快照的一部分，当前 MVP 会归一化保存已选植物、已放置植物、僵尸、投射物、波次和 tick，因而刷新可以继续当前短局；页面 timer 本身不写入存储，离开 battle 会清理 timer。后续若扩大为连续关卡，再单独评估是否只保存业务结果而不保存中间态。

## 6. 页面和模块边界

- `preschool-garden.js`：承载解锁、阳光、豌豆能量、成长奖励、版本化 `garden.defense` 规则、实体、移动、冷却、命中和迁移。
- 本轮不新增 `preschool-defense-game.js`；避免再引入一套全局模块和存档边界。
- `app.js`：负责路由渲染、事件编排、页面级 tick 生命周期和反馈动画。
- `config.js`：统一新名称、战斗页标题和版本文案。
- `preschool-workbench/index.html`、`index.html`：统一 `<title>`、品牌和入口说明。
- `css/preschool/`：只放战场布局和状态样式；不要继续把规则写进 CSS。

## 7. 明确不做

第一版不做完整原版关卡、夜间/泳池场景、植物升级树、复杂敌人 AI、掉落物物理、多人对战、联网排行榜、原版角色/音效/关卡/截图和第三方游戏 iframe。若后续确实需要大规模实体，再单独评估 Phaser，不在本轮混入。

# 幼儿学习工作台总方案

## 1. 产品结果

孩子打开页面后，60 秒内能看懂三件事：今天做哪三件小事、做完会让花园发生什么、下一步可以领取或照料什么。家长打开家长入口后，3 分钟内能知道：孩子今天做了什么、哪个技能需要复习、奖励是否需要确认。

## 2. 三层结构

| 层 | 用户问题 | 页面实现 |
| --- | --- | --- |
| 今日行动层 | 我现在做什么 | `overview` 显示 3 个核心活动，展开可选活动 |
| 学习内容层 | 我要怎么学 | `courses` 内部折叠学科组；选择课程后保留课程侧导航 |
| 成长反馈层 | 做完有什么变化 | `garden`、`growth`、`rewards` 显示阳光、植物、收藏和家长奖励 |

## 3. 幼儿交互原则

- 图标先于文字，文字只保留动作词：看、听、数、说、动、领。
- 一个页面只突出一个主要动作；避免“两个导航栏嵌套”和重复的右侧目录。
- 触控目标不少于 44px，关键卡片不少于 72px；错误反馈可恢复，不阻断页面。
- 视觉使用原创阳光花园与植物伙伴，背景是游戏场景，但学习内容仍由 HTML/CSS/JSON 清楚表达。
- 动画只反馈状态：角色轻摆、阳光飞入、豌豆命中；动画中断、浏览器不支持或开启减少动效时，状态仍可读。

## 4. 日闭环

```text
领取今日三项 → 完成一个活动 → 写入 activity event → 只发一次阳光/豌豆能量
→ 花园更新植物或防守 → 核心三项完成 → 解锁一次宝箱/连续日反馈
→ 家长可确认线下奖励 → 第二天根据复习队列生成下一项
```

未完成不扣分。僵尸/友好入侵者只表示“有一项需要回到花园处理”，不表示孩子失败。

## 5. 不做的事情

- 不把所有课程卡片放在首屏。
- 不把游戏动画当学习正确率。
- 不要求孩子持续在线；离线核心玩法必须可用。
- 不复制植物大战僵尸角色、原版截图或商业教材页面。

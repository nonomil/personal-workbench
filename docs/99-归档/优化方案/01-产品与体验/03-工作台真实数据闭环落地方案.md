# 03 工作台真实数据闭环落地方案

> 状态：**方案仍有效；`M2-UX-001a` 已写入运行代码（2026-08-13）。**  
> 范围：产品与数据闭环设计。幼儿今日工作流卡已落地；成人/少儿主路径与首页减法尚未按本方案实施。  
> 基线依据：`simpread-什么是真正的工作台.md`、优化总控、产品合同、数据兼容方案、`prj/` 当前实现证据。  
> 约束：不新增第二账本、不重新引入 Supabase、不更换 Vanilla JS 框架。

---

## 0. 一句话结论

本项目必须把“工作台”和“游戏”拆开：

- **工作台** = 真实学习/工作的入口、自动沉淀、可回看产物、下一步动作。
- **游戏** = 趣味反馈与奖励出口，只消费学习事实，不替代学习事实。

当前运行代码已有本地快照、轻量练习、错题、阅读、复盘、游戏 bridge 和奖励幂等基础；但今日页主路径仍大量依赖 `toggle-plan` 一键打卡，容易做成“看起来很努力”的任务列表。本方案把闭环从“人为打勾”收敛为“真实输入 → 自动记录 → 可见产物 → 下一步动作”。

## 1. 文章原则 → 本项目可落地点

下列原则不是摘要，而是后续页面、事件、验收的硬规则。

### 1.1 真实入口优先

| 原则 | 可落地点 |
| --- | --- |
| 工作台必须能直接干活，而不是任务发布中心 | 首页主按钮必须打开练习、阅读记录、复盘、错题复习、游戏进入页，而不是“点一下完成” |
| 入口要服务当前用户 | 成人入口是记录/推进/复盘；少儿是练习/错题/阅读；幼儿是轻量练习/今日任务映射练习/游戏出口 |
| 资料库不是首页 | 暑假资料、完整课程目录、长资料库只在学习二级页；首页不承担目录浏览 |

### 1.2 自动记录，减少人为打卡

| 原则 | 可落地点 |
| --- | --- |
| 打卡应像 GitHub 热力图：真实动作后自动生成 | 完成练习、保存阅读、结束专注、通关结算后，自动写 `dailyPlans.done`、`courseProgress`、`readingLogs`、`focusSessions`、`growth.awardedIds` |
| 人为勾选是负担，不是核心工作 | 允许兼容旧 `check-in`，但不得作为幼儿/少儿主路径；主路径是练习或真实记录 |
| 统计不能先于事实 | 连续天数、完成率、热力点只能由事实字段派生，不得手填 |

### 1.3 产物优先，而不是仪表盘优先

| 原则 | 可落地点 |
| --- | --- |
| 真正的工作台里必须有“真的东西” | 每次完成至少留下一种可见产物：练习结果、阅读记录、错题卡、复盘段落、游戏结算摘要、导出 JSON |
| 数字只是回看 | 阳光、连续天数、排行/周报只能展示事实，不能成为用户为了数字去打勾的诱因 |
| 没有产物就不算完成 | 仅 `toggle-plan` 且无 `completionSource=practice/reading/focus/review/game` 的完成，在验收中标记为弱完成 |

### 1.4 可检索沉淀

| 原则 | 可落地点 |
| --- | --- |
| 工作台是数据库 | 所有事实写入既有 localStorage 业务快照，支持 JSON 导出导入 round trip |
| 可回看、可继续 | 今日页、学习页、我的/复盘页必须能从沉淀记录打开“下一步” |
| 单一事实来源 | 三模式业务 key 不变；家庭互动继续独立 key；游戏写同一幼儿 growth，不建第二货币账本 |

### 1.5 AI / 总结入口

| 原则 | 可落地点 |
| --- | --- |
| AI 总结必须建立在真实数据上 | 只允许读取本地已沉淀字段生成总结草稿；没有记录时显示“今天还没有可总结的事实” |
| 本专项不扩 AI 运行时 | 先做“导出可总结数据包 / 本地拼装总结输入”，不接外部 AI 服务，不引入 Supabase |
| 禁止用 AI 伪造努力感 | 不得生成无事实支撑的完成记录、假证据、假连续天数 |

### 1.6 游戏与工作台分层

| 原则 | 可落地点 |
| --- | --- |
| 工作台负责真实学习/工作闭环 | 任务、练习、错题、阅读、复盘、家长反馈 |
| 游戏负责趣味与奖励出口 | 花园/方块/横版独立页面；工作台只给进入按钮与摘要 |
| 游戏不得改写学习完成事实 | 游戏 bridge 可写 `growth.worldGames` 与有上限阳光；不得把 `dailyPlans`/`courseProgress` 标为学习完成 |
| 奖励幂等 | 继续使用 `eventId` / `awardedIds`；同一学习事件不得因“打卡 + 练习 + 游戏”重复发主奖励 |

### 1.7 与既有专项原则的对齐修正

章程中“工作台负责打卡/测试/反馈”在本文件收紧为：

```text
工作台负责：真实练习/记录入口 + 自动沉淀 + 反馈 + 下一步
打卡：只能是派生视图，不是主操作
游戏：趣味反馈与奖励出口
资料库：完整内容二级入口
```

## 3. 三入口闭环定义

统一模板：

```text
真实输入 → 自动记录 → 可见产物 → 下一步动作
```

### 3.1 成人工作台

成人主价值：在工作台里完成记录与推进，而不是维护漂亮仪表盘。

#### 例子 A：阅读沉淀

1. **真实输入**：打开“阅读与记录”，填写书名/材料、分钟、页数、一句摘录。  
2. **自动记录**：写入 `readingLogs[]`；可选同步当日相关 `dailyPlans` 为 done 且 `completionSource=reading`（若实现关联）。  
3. **可见产物**：今日页出现“今日阅读：书名 · N 分钟 · 摘录”；阅读页可检索历史。  
4. **下一步动作**：提示“写一条复盘/下一步”或“继续同一本书”。

#### 例子 B：专注时段

1. **真实输入**：开始/结束一次专注，提交分钟与来源（学习/阅读/任务）。  
2. **自动记录**：写入 `focusSessions[]`。  
3. **可见产物**：周专注柱状与今日证据；归档统计派生活跃天。  
4. **下一步动作**：若有临近 milestone，跳到“项目与目标/生活节点”；否则提示记录复盘。

#### 例子 C：复盘驱动下一步

1. **真实输入**：在复盘箱写下今天发生了什么与 `nextAction`。  
2. **自动记录**：写入 `reviews[]`。  
3. **可见产物**：今日页“最近复盘 + 下一步”卡片可点击。  
4. **下一步动作**：点击卡片打开复盘详情，或根据 `nextAction` 创建/定位一条今日计划。

#### 成人降级项

- 习惯一键勾选、年度进度条、大而全生活六宫格：可保留，但移出“唯一主路径”。  
- 归档统计：派生视图，不作为完成手段。

### 3.2 少儿工作台

少儿主价值：完成真实练习/阅读，留下错题与证据，再去奖励。

#### 例子 A：今日词卡/练习

1. **真实输入**：从今日计划点“去练习/打开课程”，答对轻量题。  
2. **自动记录**：`courseProgress.completedLessonIds` 增加；关联 plan `done=true`、`completionSource=practice`；`awardSunlight(lesson:id)` 幂等。  
3. **可见产物**：今日证据“练习完成 1 张”；课程进度更新。  
4. **下一步动作**：下一张未完成练习，或错题复习，或奖励页。

#### 例子 B：错题回炉

1. **真实输入**：在错题本记录题目、错因、正解，或标记已掌握。  
2. **自动记录**：`mistakes[]` 增改；状态 `todo|mastered`。  
3. **可见产物**：错题列表与“再看看/会了”。  
4. **下一步动作**：未掌握错题优先出现在今日工作流卡。

#### 例子 C：阅读 + 家长看见

1. **真实输入**：孩子提交阅读记录；家长在家庭互动留言鼓励。  
2. **自动记录**：`readingLogs[]` + `family_updates` 消息。  
3. **可见产物**：今日证据显示阅读；家庭页显示家长反馈。  
4. **下一步动作**：孩子去奖励/成长；家长不打断学习主路径。

#### 少儿降级项

- 纯 `toggle-plan` 打卡：兼容保留，不作为首页主按钮。  
- 成长宠物/语音夸奖：反馈层，不代替练习事实。

### 3.3 幼儿工作台

幼儿主价值：3 个核心轻量练习 + 自动阳光 + 一个游戏出口。

#### 例子 A：识字/古诗/数学计划练习

1. **真实输入**：今日必做任务上点“去练习”，在 lesson dialog 答对后点完成。  
2. **自动记录**：  
   - `courseProgress.completedLessonIds`  
   - 对应 `dailyPlans`：`done=true`，`completionSource=practice`，`completionRewardId=lesson:...`  
   - `growth` 阳光经 `lesson:{id}` 幂等发放  
3. **可见产物**：今日工作流卡显示“已完成练习：xxx”；练习证据计数 +1。  
4. **下一步动作**：下一未完成必做；全部完成后主按钮变为“去当前主题游戏”。

#### 例子 B：英语小测试续学

1. **真实输入**：从“继续今天/下一张练习”进入英语 lesson。  
2. **自动记录**：同上。  
3. **可见产物**：继续学习条更新；课程徽章点亮。  
4. **下一步动作**：下一未完成 lesson 或回今日页看证据。

#### 例子 C：游戏结算反哺（非学习完成）

1. **真实输入**：从今日页进入当前主题独立游戏，通关/游玩结算。  
2. **自动记录**：bridge 写 `growth.worldGames`、游玩日、有上限游戏阳光/徽章。  
3. **可见产物**：游戏摘要、今日游玩戳；**不**把学习任务标完成。  
4. **下一步动作**：返回工作台看奖励；若学习未完成，仍提示先完成练习。

#### 幼儿明确边界

| 项目 | 是否可当学习完成事实 | 说明 |
| --- | --- | --- |
| 轻量练习答对 | 是 | 主路径 |
| 一键 `toggle-plan` | 弱 / 兼容 | 不得作为 MVP 主按钮文案 |
| 打印材料浏览 | 否 | 只是资源；无“已打印/已使用”事件前不算完成 |
| 语音夸奖开关 | 否 | 不是语音练习 |
| 家长互动 | 否 | 反馈事实，独立存储 |
| 游戏通关 | 否（学习维度） | 游戏事实单独展示 |

## 4. 最小可行版本（MVP）

### 4.1 只保留 3 个核心工作台入口 + 1 个游戏出口

面向真实使用的最小集合：

| 序号 | 入口 | 人群 | 必须能做的真事 | 首屏禁止 |
| --- | --- | --- | --- | --- |
| 1 | 成人 · 今天 | 成人 | 看临近节点；新增阅读/专注/复盘；看到最近产物与下一步 | 完整生活六宫格、年度大盘、同步后台 |
| 2 | 少儿 · 今天 | 少儿 | 打开今日练习或阅读；看到证据；去奖励 | 完整课程树、家长配置 |
| 3 | 幼儿 · 今天 | 幼儿 | 3 核心任务中的练习入口；1 张工作流卡；完成证据 | 月历、三界详细进度墙、完整游戏棋盘、家长后台 |
| 出口 | 幼儿当前主题游戏 | 幼儿 | 一次点击进入独立游戏页 | 在首页内嵌完整战斗 |

少儿/成人的“游戏”若无独立闭环，本 MVP 不强行加；幼儿保留唯一主游戏出口。奖励中心可作为完成学习后的次按钮，不算第四核心入口。

### 4.2 首页信息架构（目标表现，未实现）

```text
状态头（伙伴/日期/阳光等摘要）
→ 1 张可点击工作流卡（真实下一步）
→ 最多 3 个核心任务（练习优先，不是一键勾）
→ 今日产物/证据（无则诚实空态）
→ 主出口：去游戏（幼儿）/ 去复盘或奖励（成人/少儿）
```

### 4.3 现有模块降级清单

| 现有能力 | MVP 处置 | 原因 |
| --- | --- | --- |
| 首页主按钮 `toggle-plan` 一键打卡 | **降级为次操作或隐藏** | 人为打卡增加负担，弱事实 |
| 完成率大数字 / 每日挑战百分比 | **派生视图**，移出主视觉中心 | 防止舍本逐末 |
| 三界世界进度墙、徽章墙、周冒险报告 | **移出首页**，进游戏页/成长二级 | 游戏反馈不应压过学习入口 |
| 月历出勤、连续打卡墙 | **派生视图**，进“我的/成长” | 热力应来自真实动作 |
| 排行榜 / 联网排名 | **不做**；若有文案入口移除或禁用 | 章程非目标；易变成刷分 |
| 暑假完整资料库 | **学习二级**，禁止首页加载完整包 | 资料 ≠ 今日闭环 |
| 家长表单、导入导出、账号同步 | **我的/家长区** | 不挡儿童主路径 |
| 语音夸奖、浇水、造型 | 保留为反馈彩蛋，不进 MVP 主路径 | 非学习产物 |
| 成人习惯勾选 | 弱完成，次于阅读/专注/复盘 | 接近人为打卡 |
| 假任务列表样式的战场文案“首页只负责打卡” | **文案与交互都要改掉**（后续代码卡） | 与真实工作台原则冲突 |

## 5. 数据事件草案（不声称已实现）

以下是**设计草案**。现有代码中部分动作已接近（如 `lesson-finish`、`toggle-plan`、bridge 结算），但事件命名、统一工作流卡消费、弱完成降级等**尚未按本方案落地**。

共同约束：

1. 只写入既有业务 key / 家庭 key。  
2. 奖励继续走 `eventId` + `growth.awardedIds`。  
3. 写入失败必须 toast/可观察失败，不得显示成功。  
4. 不新增 Supabase 表，不新增第二阳光账本，不换框架。

### 5.1 事件总表

| 事件名 | 触发源 | 输入 | 持久化位置 | 展示位置 | 去重规则 | 失败反馈 |
| --- | --- | --- | --- | --- | --- | --- |
| `practice.lesson_completed` | 幼儿/少儿练习 dialog 答对后确认 | `lessonId`, 可选 `planId+date`, 作答结果 | 业务 state：`courseProgress.completedLessonIds`；可选 `dailyPlans` 同步；`growth` via `lesson:{lessonId}` | 今日工作流卡、课程进度、证据区 | `lessonId` 已在 completed 中则不再发奖；plan 同步不重复发 plan 奖 | “练习保存失败/课程不可用”，保持 dialog 可重试 |

### 5.2 今日工作流卡派生优先级（草案）

对幼儿/少儿：

1. 今日未完成且带 `practiceLessonId` 的必做 plan  
2. 未掌握错题  
3. 下一未完成 lesson（`getNextPreschoolLesson` 同类逻辑）  
4. 今日尚无阅读时的阅读入口（少儿）  
5. 全部完成后：去游戏 / 去奖励  

对成人：

1. 过期或 14 天内 milestone  
2. 今日尚无 `reviews` 且有阅读/专注事实 → 写复盘  
3. 今日尚无阅读/专注 → 对应输入入口  
4. 最近 review.nextAction  

### 5.3 明确不做的事件

- `leaderboard.*` 联网排行  
- `print.completed`（尚无打印管道与产物字段）  
- `voice.practice_completed`（尚无录音/语音评测事实源）  
- 任何写入第二 `sunlight` 余额或云端主账本的事件

## 7. 反模式清单与验收判定

### 7.1 “看起来很努力但没有真实产物”反模式

1. **首页靠一键打勾冲完成率**，不进练习、不留阅读/复盘。  
2. **为阳光/连续天数反复取消再勾选**（若逻辑允许）制造热力。  
3. **统计卡片很多，但点进去没有可继续的工作**。  
4. **用游戏通关冒充学习完成**。  
5. **用 AI 生成总结/假证据，而本地无对应记录**。  
6. **把资料库浏览、打印版打开、语音夸奖开关算作学习完成**。  
7. **家长代勾全部任务，孩子没有练习交互**。  
8. **第二账本或临时积分**让数字“更好看”。  
9. **排行榜、徽章墙占据首页**，真实下一步折叠到二级。  
10. **空态用假种子数据装作今天已完成**（演示种子可以，但不得在验收口径里算用户真实产物）。

### 7.2 验收时如何判定不是形式主义

每条必须同时满足：

| 检查 | 通过标准 | 失败标准 |
| --- | --- | --- |
| 真实入口 | 主 CTA 打开练习/记录/复盘/游戏页 | 主 CTA 只切换 `done` 布尔值 |
| 自动记录 | 动作后 localStorage 对应字段变化可核对 | 只有 UI 高亮，刷新丢失或字段未变 |
| 可见产物 | 能指出一条具体记录（lesson id、阅读条、复盘正文、游戏结算） | 只有“已完成 3/3”百分比 |
| 下一步 | 完成后卡片指向下一真实动作 | 完成后只撒花或堆勋章 |
| 分层 | 游戏结算不改学习 plan 完成 | 玩游戏后学习任务自动全勾 |
| 幂等 | 重复提交不双倍阳光 | 同一 lesson/plan 多次 +阳光 |
| 失败可见 | 存盘失败有错误提示且不显示成功 | 失败仍提示“完成啦” |
| 导出一致 | 导出 JSON 含该条事实，导入后仍在 | 只有界面有、快照无 |

推荐最小验收剧本（幼儿）：

```text
1. 打开幼儿今日页
2. 点击工作流卡“去练习”
3. 答对并完成
4. 确认 courseProgress 与 plan.completionSource=practice
5. 确认阳光 awardedIds 含 lesson:xxx 且刷新后仍在
6. 确认首页工作流卡指向下一项或游戏出口
7. 进入游戏游玩后返回：学习完成状态不被游戏改写
```

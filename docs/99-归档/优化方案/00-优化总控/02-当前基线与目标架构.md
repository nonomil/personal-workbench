# 02 当前基线与目标架构

## 1. 审计范围

本次只审计当前工作树实际运行路径：

- 根选择页：`prj/index.html`
- 成人入口：`prj/成人成长工作台/index.html`
- 少儿入口：`prj/儿童学习工作台/index.html`
- 幼儿入口：`prj/preschool-workbench/index.html`
- 共享运行时：`prj/app.js`、`prj/config.js`、`prj/storage.js`
- 幼儿成长与游戏：`prj/child-growth.js`、`prj/preschool-garden.js`、`prj/games/`
- 样式：`prj/css/`
- 发布：`scripts/prepare-mobile.mjs`、`scripts/release-verify.mjs`、`.github/workflows/android-apk.yml`

`docs/` 中的历史愿景、旧行号和日期计划不能覆盖当前代码事实。

## 3. 必要复杂度

下列能力有真实用户价值，应保留：

- 成人、少儿、幼儿三种模式。
- 幼儿三种游戏世界，但它们是同一工作台的主题/游戏入口，不是三套数据系统。
- 本地优先、JSON 导入导出、账号同步可选降级。
- 任务和课程完成的幂等奖励。
- 阳光、豌豆能量、长期成长与奖励兑换。
- 花园、方块、横版三个独立小游戏。
- 学习任务、轻量练习、错题和家长确认。
- GitHub Pages、Capacitor APK 共用一份运行时。

## 4. 偶然复杂度

下列复杂度不是产品必须，而是历史叠加造成：

- 三种幼儿主题在根入口占三张工作台卡。
- 幼儿侧栏 17 个编号入口。
- 首页同时渲染主题横幅、伙伴、任务战场、世界进度、证据、节奏和出口。
- 成人、少儿、幼儿共用同一份页面渲染函数集合。
- 课程定义、素材路径、页面元数据和主题配置集中在 `config.js`/`app.js`。
- CSS 通过 `final-*`、`correction`、`restore`、`override` 持续纠偏。
- APK 复制全部素材目录，而不是运行时白名单。
- 日期计划、课程总控、项目总控和 worktree 文档反复描述同一状态。

## 5. 优化目标

### P0：减小认知负担

- 三工作台入口。
- 幼儿五主导航。
- 首页单一任务闭环。
- 家长和系统能力退出儿童首层路径。

### P1：降低改动风险

- 先拆模式渲染器，再拆页面，不做一次性重写。
- 页面进入时才加载该模式/课程所需脚本。
- 存储、奖励和路由接口保持稳定。

### P2：减小发布体积

- 运行素材与研究素材物理分层。
- APK 和 Pages 共用白名单制品。
- 历史 worktree、dist、android、node_modules 移出项目根，但只能在核验后进行。

## 6. 停止扩张规则

优化期间冻结以下新增需求：

- 新学科、新货币、新成长系统。
- 新游戏世界和更多关卡。
- AI 自动出题、联网排名、社交。
- 完整课程播放器或大规模内容导入。
- 全面更换技术栈。

只有当前 P0/P1 门禁通过且真实用户反馈证明有必要，才重新评估这些需求。

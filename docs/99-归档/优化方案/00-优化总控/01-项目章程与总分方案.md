# 01 项目章程与总分方案

## 1. 主目标

把个人工作台从“功能集合门户”收敛为三个有明确人群的轻量工作台，并让复杂课程和游戏以二级功能/独立页面存在。

## 2. 可衡量目标

- 根入口：5 张卡减少为 3 张卡。
- 幼儿一级导航：17 项减少为 5 项。
- 幼儿首页：最多四个业务区块。
- 首屏：不加载完整暑假资料和全部游戏资源。
- `app.js`：不再同时包含三模式全部页面渲染实现。
- CSS：幼儿入口从 28 层导入收敛至最多 6 层。
- Artifact：阻止 raw/reference/split 等进入发布制品。
- 数据：三业务 key 和两个 launcher key 不变，导入导出 round trip 通过。

## 3. 非目标

- 不增加课程内容数量。
- 不增加第四个用户模式或第四款游戏。
- 不重做三款游戏的玩法和美术。
- 不建设完整家长后台、社交和排行。
- 不更换 Vanilla JS 技术栈。
- 不在本专项解决正式签名、商店上架或复杂多端合并。

## 4. 总分结构

```text
总专项：个人工作台减重与模块化
├─ A. 治理和迁移基线
│  ├─ 解释当前脏工作树
│  ├─ 确认 prj 是唯一运行源
│  └─ 建立可恢复检查点
├─ B. 产品减法
│  ├─ 三工作台入口
│  ├─ 幼儿五导航
│  ├─ 首页四块
│  └─ 二级功能归并
├─ C. 技术模块化
│  ├─ runtime/adapter
│  ├─ 幼儿五页面模块
│  ├─ 课程按需加载
│  └─ 成人/少儿 adapter
├─ D. 样式和素材治理
│  ├─ CSS 六层
│  ├─ 运行素材目录
│  └─ artifact 白名单
├─ E. 数据兼容
│  ├─ localStorage/奖励
│  ├─ 导入导出
│  └─ 旧路由兼容
└─ F. 质量和发布
   ├─ Node/浏览器
   ├─ Pages artifact
   └─ APK/MuMu
```

## 5. 核心原则

1. 减少暴露，不等于删除底层能力。
2. 先产品边界，后代码拆分，最后清理文件。
3. 先保数据，后改界面。
4. 按任务卡小步执行，不允许大爆炸重写。
5. 工作台负责打卡/测试/反馈，游戏负责趣味，资料库负责完整内容。
6. 只有 runtime 白名单进入制品。
7. 所有“完成”必须有对应级别的证据。

## 6. 角色

| 角色 | 责任 |
| --- | --- |
| 用户/产品负责人 | 确认产品减法、主题入口和里程碑用户门 |
| Codex 主控 | 维护任务卡、审查 diff、测试、数据和发布证据 |
| Grok Build 实施代理 | 在文件白名单内执行单张任务卡，不拥有发布权 |
| 验收者 | 浏览器和设备操作，确认不是只过静态测试 |

## 7. 完成与削减

P0 数据、重复奖励、路由和恢复问题必须为 0。若排期或复杂度超出预期，优先削减成人/少儿导航美化和深度 CSS 重构，不削减数据兼容、幼儿主路径和 artifact 白名单。

# 02 加载性能与生命周期

## 加载分层

### 所有模式必需

- launcher/variant 配置。
- storage repository。
- core shell、router、toast/dialog。

### 当前模式必需

- adult adapter、child adapter 或 preschool adapter，只加载一个。

### 页面按需

- 课程数据和暑假资料。
- 账号同步 UI。
- 三款游戏自己的脚本和大图。

## 首屏预算

- 不请求 `preschool-summer-learning-data.js`。
- 不请求未选择主题的游戏背景。
- 不创建游戏 timer、Speech utterance 和课程 fetch。
- 只加载根/当前模式的运行素材。

## 页面 owner

每个页面模块必须拥有并清理自己的：timer、AbortController、语音、键盘监听和临时动画。`onLeave()` 后旧页面不得再调用 render 或写状态。

## 错误状态

- 核心 adapter 缺失：页面内错误，不显示空白。
- 课程 fetch 失败：说明“资料暂未加载”，保留返回和重试。
- 图片失败：文本、CSS 背景或占位图仍能表达操作。
- 写入失败：不显示完成、不发奖，给家长可读提示。

## 性能记录

每个里程碑记录首屏请求数、JS/CSS/图片传输大小、DOMContentLoaded/可交互近似时间。目标用于比较，不用伪造实验室精度。

# 01 技术模块化方案

## 1. 原则

- 保持 Vanilla JS、IIFE/命名空间和静态部署。
- 先建立清晰边界，再缩短文件；行数不是唯一目标。
- 不改变存储和奖励事实来源。
- 不做一次性重写；每次抽取后测试和提交。
- 共享模块只保存真正共享的壳层能力，不能把三套业务继续塞回 `shared`。

## 3. 公开接口

### Core

```js
window.PersonalWorkbenchRuntime = {
  context,
  navigate(page, options),
  render(),
  registerVariant(id, adapter),
  showToast(message, tone),
  openDialog(type, payload)
};
```

### Variant adapter

```js
{
  id: 'preschool',
  normalizeRoute(route),
  getPageMeta(page),
  renderPage(route, derived),
  handleAction(action, element, event),
  onEnter(route),
  onLeave(route)
}
```

页面模块返回 HTML 或 DOM 片段，不直接写 localStorage。状态变更继续通过 repository、成长模块、课程模块和游戏 bridge。

## 4. 渐进拆分顺序

### 第一步：只拆纯函数和素材解析

从 `app.js` 抽取：

- 幼儿主题 playbook。
- 素材路径解析和 fallback。
- 路由解析、hash 格式化。
- 不依赖闭包状态的 HTML helpers。

先注册到唯一 PascalCase 命名空间，并保持旧函数作为薄代理，避免大面积改调用点。

### 第二步：拆幼儿五个页面渲染器

按页面逐个抽取，优先顺序：

1. `today.js`
2. `learning.js`
3. `games.js`
4. `rewards.js`
5. `profile.js`

每抽一页：先增加合同测试，再迁移函数，再确认旧函数只剩代理，最后删除已无调用的实现。

### 第三步：拆事件处理

当前集中点击处理应按 action owner 路由：

- 壳层：导航、侧栏、弹窗关闭。
- 幼儿页面：计划、练习、奖励、主题选择。
- 游戏：由独立游戏页面拥有 timer 和输入。
- 账号：由 `api-adapter.js` 或后续 account controller 拥有。

核心事件缺失时必须提示，不允许静默跳过。

### 第四步：拆成人与少儿

幼儿稳定后，再把成人和少儿渲染器移出 `app.js`。三套入口分别加载自己的 adapter；不打开的模式不下载对应页面代码。

## 5. 配置与课程数据

`config.js` 最终只保留：

- 模式 ID、标题、路径、存储 key。
- 页面元数据。
- 幼儿主题元数据。

幼儿课程条目迁移到 `prj/data/preschool/` 的 JSON 或独立数据脚本。学习页首次进入时再加载，失败时显示明确 fallback。

`preschool-summer-learning-data.js` 不应在首页同步加载。过渡方案：只有进入暑假资料页面时由 loader 注入脚本；最终方案：转为 JSON 并使用 `fetch()` 检查 `response.ok`。

## 6. 生命周期

每个页面 adapter 必须提供 `onLeave()`：

- 清理 `setInterval`。
- 清理延迟动画。
- 取消未完成 fetch。
- 停止 Web Speech。
- 防止旧页面回调重绘当前页面。

独立游戏继续自己拥有循环；工作台页面不得重建游戏 tick。

## 7. 完成定义

- `app.js` 不再包含三套完整页面 HTML。
- 成人入口不加载幼儿课程和游戏渲染模块。
- 幼儿首页不加载暑假资料和完整课程数据。
- 任一页面刷新、返回、导入快照后的行为与拆分前一致。
- 不新增 localStorage key 或第二套奖励 API。

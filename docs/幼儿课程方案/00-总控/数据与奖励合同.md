# 数据与奖励合同

## 1. 唯一事实来源

- 运行状态继续使用现有幼儿快照 `petbank_huchuliang_preschool_workbench_state_v1`。
- 课程完成继续使用 `courseProgress.completedLessonIds`；需要掌握度时只在其下增加 `courseProgress.phonics` 等命名空间。
- 阳光余额、累计阳光、花园成长点、豌豆能量分离；任何学科不得直接写 localStorage。
- 日期身份统一使用本地 `YYYY-MM-DD`，审计时间才使用 ISO 时间戳。

## 2. 活动事件

```json
{
  "activityId": "activity-2026-08-02-math-001",
  "profileId": "local-default",
  "subject": "math",
  "lessonId": "preschool-math-day-001",
  "status": "completed",
  "evidence": ["counted-objects", "selected-more"],
  "rewardEventId": "activity-2026-08-02-math-001:complete"
}
```

奖励服务只接受稳定 `rewardEventId`。首页、课程页、今日页从不同入口完成同一活动时，后到者返回 duplicate，不再次增加阳光。

## 3. 奖励口径

| 行为 | 阳光 | 豌豆能量 | 备注 |
| --- | ---: | ---: | --- |
| 核心活动完成 | 10 | 1 | 每个活动实例一次 |
| 可选复习完成 | 5 | 0 | 不完成不扣分 |
| 当天首次有效行动 | 10 | 0 | 写入 `checkinDates`，一天一次 |
| 三项核心全部完成 | 20 | 1 | 以日闭环事件一次结算 |
| 浇水 | 消耗 5 | 0 | 每天一次，失败不改状态 |
| 发射豌豆 | 0 | 消耗 1 | 命中只改变入侵者状态 |
| 家长线下奖励 | 消耗约定阳光 | 0 | `pending → approved → claimed` |

## 4. 错误和离线

- 错题、复习和重新尝试不扣阳光。
- 写入失败时 UI 不显示“已完成”，并给出重试提示。
- 同步冲突保留本地快照，不自动覆盖；只有实际 pull/恢复成功后才显示已同步。

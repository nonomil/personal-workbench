# 总实施计划

## 模块边界

| 模块 | 负责内容 | 禁止负责 |
| --- | --- | --- |
| `course-catalog` | 静态课程目录和筛选 | 直接发阳光 |
| `activity-runner` | 活动会话、尝试、证据 | 直接改余额 |
| `reward-service` | reward event 幂等结算 | 根据动画结算 |
| `preschool-garden` | 花园、植物、入侵者和能量消费 | 判定学习是否掌握 |
| `parent-review` | 家长观察、奖励确认和复盘 | 修改儿童答案 |
| `api-adapter` | 登录、快照上传/恢复 | 覆盖本地失败状态 |

## 每个学科接入顺序

1. 静态 JSON 和 schema 测试。
2. 今日活动实例生成。
3. 活动对话框和证据提交。
4. reward event 接入。
5. 课程页/首页推荐复用。
6. 花园反馈和家长观察。
7. 移动端、导入导出、同步和发布验收。

## 完成定义

没有“页面能打开但没有内容”的中间完成态。一个学科只有同时具备内容条目、活动证据、复习队列、奖励幂等、错误反馈、家长观察和测试，才算完成第一版。

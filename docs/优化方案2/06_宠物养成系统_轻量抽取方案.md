# 宠物养成系统 · 轻量抽取方案（classroom-pet-system / StarKids / pet-bank / Chirpie）

> 背景：分析多个宠物养成开源项目，判断哪些部分可以"轻量化抽取"到工作台，哪些"太重应该跳过"。

---

## 一、抽取原则

三条轻量抽取的红线：

| 原则 | 说明 |
|------|------|
| 只抽模式，不搬代码 | 借鉴数据结构和交互逻辑，不直接复制整个模块 |
| 降维到幼小衔接 | 去掉教师端、排行榜、复杂权限，只保留孩子端核心体验 |
| 单文件可承载 | 抽取内容必须能在现有单HTML中增量实现，不引入新框架 |

---

## 二、各项目抽取分析

### 2.1 classroom-pet-system（课堂宠物系统）

**项目定位**：学生完成课堂任务赚积分→购买道具→养成专属宠物

**可抽取的轻量内容**：

| 模块 | 原实现 | 轻量抽取 | 代码量 |
|------|--------|---------|--------|
| 四维状态 | 生命、饱食、心情、清洁 | 只取**饱食度**一维（幼小衔接够用） | ~30行 |
| 状态衰减 | 随时间衰减 | 每小时-2，存时间戳计算 | ~20行 |
| 成长阶段 | 7个阶段（蛋→刚出壳→幼宠→成长→成熟→进化→传说） | 精简为**4阶段**：蛋→幼崽→成长→进化 | ~40行 |
| 经验系统 | 每日经验上限50，全程约6年满级 | 每日上限30，全程约30天满级（匹配打卡周期） | ~30行 |
| 道具系统 | 积分购买食物、清洁、玩具、医疗 | 只保留**食物**（积分换饲料），去掉清洁/玩具/医疗 | ~20行 |
| 宠物互动 | 喂食、洗澡、玩耍、治疗 | 只保留**喂食**和**点击抚摸** | ~30行 |
| 状态警告 | 低于阈值显示提示 | 保留：饱食度<20显示「😢好饿」 | ~15行 |

**跳过（太重）**：
- 教师端任务管理
- 班级排行榜
- 管理员端账号管理
- 背包系统分类筛选
- 死亡复活机制（对幼小衔接太残酷）
- Vue3框架+多文件组件结构（工作台是单HTML）

**核心数据模型（抽取后）**：
```javascript

  type: 'dragon',        // 宠物种类（对应主题）
  name: '小火龙',        // 宠物名称

  exp: 0,                // 当前经验
  maxExp: 100,           // 升级所需经验（逐级递增）
  hunger: 80,            // 饱食度 0-100
  lastUpdate: timestamp, // 上次更新时间（用于计算衰减）
  feedCount: 0           // 累计喂食次数（用于成就）

```

**经验值设计（参考原项目GROWTH_STAGES）**：
```javascript
// 原项目GROWTH_STAGES从level 0到20，工作台精简为4阶段，总经验需求约1000

  { stage: 0, name: '蛋', emoji: '🥚', maxExp: 50 },
  { stage: 1, name: '幼崽', emoji: '🐣', maxExp: 150 },
  { stage: 2, name: '成长体', emoji: '🐾', maxExp: 400 },
```

### 2.3 pet-bank（积分银行·核心参考）

**项目地址**：`https://github.com/nonomil/pet-bank`（公开仓库，但页面无法直接访问）

**从公开信息可抽取的理念**：

| 理念 | 说明 | 工作台实现 |
|------|------|-----------|
| 积分银行 | 完成目标→积分存入→积分用于养宠 | 学习任务完成→获得积分→积分兑换饲料 |
| 宠物成长 | 积分累积→宠物进化 | 经验累积→阶段晋升 |
| 场景探索 | 随积分解锁新场景 | 随打卡天数解锁成长世界新元素 |
| 版本化快照 | 支持数据快照和恢复 | 已有导出/导入功能，可增强 |

抽取方式：不复制代码，只借鉴"积分→宠物"的**因果链设计**——让孩子明确看到"我完成了任务→宠物变好了"。

**pet-bank更详细的能力盘点（在能打开在线演示页面后补充）**：

| 维度 | pet-bank的做法 |
|------|----------------|
| 核心理念 | "把完成目标包装成账户余额增长，把坚持习惯包装成宠物养成" |
| 孩子端 | 纯前端，localStorage离线运行，刷新不丢数据 |
| 家长端 | 同域Node.js+SQLite管理账号、家庭、孩子档案 |
| 宠物种类 | 已接入238种（original/banchong/classpet/minecraft/pvz） |
| 成长阶段 | 蛋→幼崽→成长→进化（生蛋机制v0.6.0已实现） |
| 积分体系 | 积分兑换商店+奖励兑换+盲盒稀有度分层 |
| 场景探索 | 12大奇幻场景随积分解锁 |
| 数据安全 | 版本化快照、导出/导入备份 |
| 跨设备 | 可选VPS自托管同步，不依赖Supabase |

**最值得抽取的轻量模块（更新版）**：

1. **宠物数据模型**（约30行）——从pet-bank的"宠物养成系统深化"抽取核心数据结构：
```javascript
const PET_DATA = {
  type: 'dragon', name: '小火龙', stage: 0,
  exp: 0, maxExp: 50,
  hunger: 80, lastUpdate: Date.now(),
  totalFeed: 0, unlockedAt: Date.now()
};
```

2. **积分银行模式**（理念层，约0行代码）——积分不是消耗品，而是"存款"，孩子看到余额增长本身就是正反馈。工作台直接采用：**积分只增不减，用于兑换饲料/皮肤，但不因兑换而减少总量**（或保留总量统计）。

3. **版本化快照**（约50行）：
```javascript
function exportSnapshot() {
  const data = {
    version: '1.0', exportedAt: Date.now(),
    pet: loadPetData(), garden: loadGardenData(),
    map: loadMapData(), builder: loadBuilderData()
  };
  return JSON.stringify(data);
}
function importSnapshot(jsonStr) {
  const data = JSON.parse(jsonStr);
  if (data.version !== '1.0') return { error: '版本不兼容' };
  Object.keys(data).forEach(key => {
    if (key !== 'version' && key !== 'exportedAt') {
      localStorage.setItem(`pet_${key}`, JSON.stringify(data[key]));
    }
  });
  return { success: true };
}
```

4. **宠物种类映射**（约40行）——pet-bank已接入238种宠物，按主题分类，工作台只需取其映射逻辑：
```javascript
const THEME_PETS = {

  '马里奥': { id: 'mario', name: '奇诺比奥', emoji: '🍄' },
  '宝可梦': { id: 'pokemon', name: '伊布', emoji: '⚡' },
```

5. **成就/勋章系统**（约60行）——pet-bank的roadmap包含"阶段性勋章系统（连续7天、30天、100天）"：
```javascript
const BADGES = [

function checkBadges() {
```

**应该跳过的部分**：

| 模块 | 原因 |
|------|------|
| VPS自托管后端 | 工作台定位是单HTML文件，不需要服务器 |
| 兄妹PK模式 | 幼小衔接阶段不需要PvP |
| AI任务推荐 | 超出工作台范围 |
| 成长报告PDF | 可做简化版（HTML打印），不需要完整PDF生成 |
| 238种宠物 | 工作台只需要5-6种主题映射 |
| 盲盒稀有度分层 | 对幼小衔接来说太复杂 |

**一句话总结**：pet-bank最值得抽取的是"积分银行"理念+宠物数据模型+版本化快照，约180行代码即可复现其核心价值。其他如VPS自托管、PK模式、PDF报告等功能，与工作台"单HTML文件"的定位不匹配，应该跳过。

### 2.4 Chirpie（虚拟宠物伙伴）

**项目定位**：Tamagotchi风格的虚拟伙伴，通过完成现实任务（打扫、学习、正念）赚币来喂养

**可抽取的轻量内容**：

| 模块 | 原实现 | 轻量抽取 | 代码量 |
|------|--------|---------|--------|
| 任务→币→喂食 | 完成任务赚币→喂食宠物 | 完成任务得积分→积分换饲料→喂食 | 已有积分系统 |
| 状态实时更新 | 幸福值和健康值实时追踪 | 饱食度实时更新（进入页面时计算衰减） | ~20行 |

**跳过（太重）**：Arduino硬件和C++代码；TFT触摸屏和3D打印设计；M&M糖果分配器物理奖励

### 3.2 完整宠物数据模型（抽取整合版）

```javascript
// ===== 宠物数据模型（从各项目抽取整合） =====
const PET_DATA = {
  // 基础信息（参考 StarKids 的宠物种类）
  type: 'dragon', name: '小火龙',
  // 成长阶段（参考 classroom-pet-system 的 GROWTH_STAGES，精简为4阶段）
  stage: 0, exp: 0, maxExp: 50,
  // 状态（参考 classroom-pet-system 的四维，精简为一维）
  hunger: 80, lastUpdate: Date.now(),
  // 统计（用于成就）
  totalFeed: 0, totalTasks: 0, unlockedAt: Date.now()
};

// ===== 成长阶段定义（参考 classroom-pet-system） =====
const STAGES = [
  { stage: 0, name: '蛋', emoji: '🥚', maxExp: 50 },
  { stage: 1, name: '幼崽', emoji: '🐣', maxExp: 150 },
  { stage: 2, name: '成长体', emoji: '🐾', maxExp: 400 },
  { stage: 3, name: '进化体', emoji: '🦸', maxExp: 1000 }
];

// ===== 状态衰减（参考 classroom-pet-system 的衰减机制） =====
function calcHunger(pet) {
  const hours = (Date.now() - pet.lastUpdate) / 3600000;
  return Math.max(0, pet.hunger - hours * 2);
}

// ===== 喂食逻辑（参考 Chirpie 的喂食机制） =====
function feedPet(pet) {
  if (feedCount <= 0) return { success: false, msg: '饲料不够啦！' };
  feedCount--;
  pet.hunger = Math.min(100, pet.hunger + 20);
  pet.totalFeed++;
  pet.exp += 10;
  // 检查升级（参考 classroom-pet-system 的升级检查）
  while (pet.exp >= STAGES[pet.stage].maxExp && pet.stage < 3) {
    pet.stage++;
    showEvolutionAnimation();  // 进化动画
  }
  return { success: true };
}
```
